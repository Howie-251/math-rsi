# 单题工作区：让下一个行动能接上已有研究

工作区记录正在解决的数学问题。它与 MathRSI 代码版本、可复用领域知识分开；换技能或更新代码，不应覆盖原证明与证据。这里给出一种足够小的起步方式，而非所有任务都必须生成的文件清单。

## 1. 已有项目先恢复，新题再建立

如果目录已有正式规格、恢复入口和 research wiki，先读这些入口，再根据当前义务找到原始证明、程序或计算记录。不要另造一套同名导航、清空 wiki，或以旧报告中的“运行中”判断任务当前状态。需要修改历史结论时说明依据，保留原始记录。

新题先写清原命题与验收。短证明可以只在一个文档中放命题、推导和结论；会跨轮的研究通常需要如下材料：

```text
my-problem/
  FORMAL_SPEC.md           # 原对象、量词、假设、目标与接受的依赖
  NEXT_SESSION.md          # 当前已知、实际缺口、正在运行什么、下一步
  proof/                  # 当前可读论证及必要的局部引理
  research-wiki/           # 使用 ARIS wiki 时按它的实际结构维护
  work/                   # 按具体行动保存输入、脚本、结果、日志
```

目录按需要出现。只有文献任务才维护文献材料，只有计算任务才出现执行日志；不要让启动研究变成准备大量空文件。

五组子流程的具体使用见 [WORKFLOWS](WORKFLOWS.md)。它们交接的是实际数学结果，下面只是新任务尚无命名约定时的默认产物参考；恢复旧项目时沿用原文件与入口，不为匹配本表复制另一套正文。

|进入阶段|默认产物或已有等价材料|后继实际读取与使用|
|---|---|---|
|prepare：specify初步→survey→specify定稿|`FORMAL_SPEC.md`、`LITERATURE.md`、原资料目录与wiki|原量词、参数、允许终点、完整进口条件、基线和待读来源|
|route-loop|`ROUTE_REPORT.md`、实际推导／探针与审阅trace|选定方法、未证条件、首批精确任务和失败证据|
|prove|`PROOF_DRAFT.md`，复杂任务可沿用`OBLIGATIONS.md`，行动目录保存实际证据|已证明什么、如何供给真实caller、尚缺哪些原题连接|
|verify内部assemble|`PROOF.md`或现有TeX入口|从原输入到结论的完整候选；散落论证不再只以文件清单代替连接|
|verify|`VERIFICATION.md`，链接上游真实`PROOF_AUDIT`、独核及按需Lean证据|各检查准确范围、原题状态、具体修复或最终交付条件|
|handoff|`HANDOFF.md`、用户需要的阅读／复现材料、`NEXT_SESSION.md`|读者能查验的结论及接手者可直接执行的下一动作|

八个数学技能由主入口衔接，只有五组子流程；specify、survey属于prepare，assemble属于verify。局部证明或短任务可以在一份正文中保留命题、推导和核验，不为经过每个动作建立空文件。`NEXT_SESSION.md`由当前协调者唯一维护，worker回交新增事实与证据位置；wiki按原结构持续更新，不只在交付末尾补写。

使用 ARIS `research-wiki` 时先读本仓相应宿主的完整技能及 base/tools helper 说明，由它维护原有图结构和知识条目；这里不重新规定另一套 wiki schema。本仓已带该技能与 helper；运行依赖异常时先保存普通 Markdown 事实，修好实际调用后同步，不能声称失败的 helper 已执行。

自动生成的 `query_pack.md` 是导航，不保证收入全部已存事实。本次实际试用中，positive idea 的 Thesis/Key risks 已写入实体页，却没有进入自动摘要。恢复时按当前义务读取相关实体页，在 `NEXT_SESSION.md` 直接指向关键结论、条件与未闭义务；写入后读回相应实体即可，不必为此修改上游 helper 或重复整套研究。具体行为见[独立试用](../development/propertyb-rebuild/forward-use/REPORT.md)。

## 2. 正式规格要让两个人读出同一个问题

写明原对象是什么、量词覆盖哪里、给定哪些参数和假设、目标允许哪些解答。把新加的技术条件放到候选引理里，不偷偷加到原题里。

例如“找到一个满足约束的矩阵”只要求一个可靠见证；若同题允许证明不存在，则另一终点必须覆盖原始全域。二者可以共用检索与程序，但验收不是同一个布尔字段。“给所有超图证明可染”也不同于“给这一个超图找到染色”。

文献定理、已证明结果、暂时接受的进口、尚未成立的候选分开说清。需要用户决定的关键歧义尽早提出；其余可依据上下文做合理约定并继续独立工作。核心数学定义值得用一两个边界例子反译确认，而不是每次都全面重读原题。

如果已有原规格，保持其文件名与入口。新题建立自己的规格，不能把旧结论改写成新任务状态。

## 3. 把研究行动写到能执行的程度

Root 选择下一项行动时，用自然语言回答五件事即可：当前缺什么；准备做什么；输入与允许假设是什么；产物将如何改变整体证明；给多少资源、什么情况停止。简单行动一句话足够，昂贵行动才需要更具体的规模和预算。

每批派工前、收件后，都把局部成果放回原目标的关键连接、全域覆盖和端到端成本中判断。同一瓶颈连续两批没有决策增量，或局部成果不断增加而上述整体瓶颈未变，或到达预设检查点／扩批预算，就按[全局重评合同](../base/skills/mathrsi-research/references/global-reassessment.md)执行：默认两位独立只读代理分别核原题连接／路线和总成本，必要分歧加第三位；Root 消费后实际执行有界续行、补连接、换表示、转路线、装配或收束。触发后不扩旧路线；已有有用在途计算和证据继续保留。已知可承接、完成即可关闭原义务的全域必要计算正常推进，短证明不机械评审。

下面是格式示例，不是已完成的数学结论：

```text
义务：证明所有实际输入都能选到引理 L 所需的结构。
已知：L 的条件结论已核对；当前仅缺选取，不缺数值表。
行动：尝试用同一原对象的总量约束证明选取，保留失败配置。
交付：选取引理及原输入调用，或具体说明哪一步不能成立。
预算：本批有界推导；若仍只得到局部改善，回到其它表示比较。
```

多个结论需要同一组选择时，应在这里声明共同对象和坐标。否则几个各自正确的代理结果可能无法合并。代理需要相关文件和明确写入范围；不需要整段无关对话历史。

新规约另说明规约前后未闭义务、原对象数及其后继联合域、可调用工具与完整执行成本。仅闭合新规约自身引入的包装引理，不等于原题更容易。连续研究预先写具体批数／时间／计算范围的检查点；没有任务约定时，同一路线默认三个实质批次后重评，已评过的必要有限完成计划按共享协议推进。

命令和耗时记在行动目录中；证据文件很大时保存复现入口及实际存储位置。需要能找回支撑论断的输入和输出，不要求每轮重新复制所有材料。

路线或证明中出现新的术语、遗漏进口或反例问题，带当前式子、已查来源和具体疑问调用survey，收回原文条件后回到同一义务。verify若只验证一个引理，返回原prove调用点；已有完整证明则直接verify。改变核心对象／方法或全局重评决定转路线时回route-loop，不因每个索引错误重做整个准备阶段。

## 4. 恢复入口应短于完整研究史

`NEXT_SESSION.md` 让接手者知道原目标、当前可信结果、具体未闭义务、在途进程／代理与下一项行动。它保存当前快照，完整证明与失败历史通过链接找到。全局重评的实际意见、Root 决定、已执行动作及下一次触发点写入原报告，并在本恢复页链接；不新建平行总账，也不因此自动暂停 Goal。

更新时改写对应的当前条目，替换已失效状态；完整实验经过和旧决定留在已有研究记录中。旧恢复页包含别处没有的历史时，先将那部分保存到原研究记录，再用链接替换，不为缩短入口丢失证据。其他导航只保留必要入口与链接，不复制同一长篇进展；自动生成的query pack仍由原helper维护，不手工追加平行状态。worker返回新增事实与证据位置，由协调者维护这一份当前快照。

```text
原题入口：FORMAL_SPEC.md。
已成立：引理 L（证明与证据位置）；固定域 D 的排除（准确条件）。
尚未闭合：任意原对象是否都进入 D；另一条路线 A 当前独立开放。
近期判断：停止扩大局部表，因为它未保留共同约束 C。
值得重试的条件：证明 C 的新连接，或发现当前必要模型可进一步收紧。
在途任务：没有／具体进程、代理、产物目录与实际状态。
下一步：明确待解决问题和首先应读的文件。
```

有重大结果、反例或路线改变就更新。持续研究应定期整理，但不为定时器额外编写汇报。用户的 Goal、暂停、预算约定由实际宿主和任务管理；文档中的“继续”不是重启 Goal 的授权。

停止时区分：任务完成、该范围已闭、当前路线无新增信息、资源耗尽、缺依赖、用户暂停。计算预算耗尽可以在得到相应资源后继续；已完整扫过的同一域不能仅换种子重跑。未完成永远不因时间耗尽改写成完成。

子流程的局部轮次或探索预算用尽，先把真实结果和下一动作返回调用方。它不自动改变Goal状态，也不阻止其它独立的已授权工作；整个Goal的暂停、总预算和恢复按实际用户指令与宿主状态处理。

## 5. 提交可检查的解答

自然语言成稿用定义、定理／引理、证明组织。每个假设写在结果处，每个引用指向实际版本与定理或公式。正文接通原问题；必要证明不能只散落在未说明的 MD 链接后面。

计算证据随同说明实际输入、遍历范围、完整性依据和复核命令。Lean 项目给原题声明、实际构建目标、固定依赖与审计入口；默认 build 成功不自动说明构建了所需新主定理。跨模型意见另列实际阅读与执行范围。

需要分享时调用 ARIS `render-html` 或合适的文档工具，把完整可读故事整理成一份入口，再提供深层源码。对外呈现贡献与证据，不用内部纠错日志淹没正文；原日志仍留作查验。是否需要 PDF、HTML、Lean 或大型证据包由任务决定。

## 6. 用哪个版本、怎样更新

任务起步或切换版本时记录 MathRSI 提交与启用的插件，ARIS 技能按实际来源记录。开发中的未提交内容如实注明；不凭目录名字伪造版本绑定。

工作区可以位于仓库外，通常正是原研究目录。若临时放在仓库的 `workspaces/`，它默认不进入代码 Git；重要研究资料仍须按自己的数据保存方式保留。`.gitignore` 不是备份。

需要给通用流程提改进时，记录触发问题、建议行为和可检查例子，再按[独立维护工作流](EVOLUTION_WORKFLOW.md)在MathRSI开发分支实施、试用和决定是否纳入。由维护owner消费真实结果，记录实际版本及原任务何时采用；单题使用过程中不自行改变核心完成标准。关于插件如何交流见 [协作约定](PLUGIN_CONTRACT.md)。

## 7. 五阶段的 wiki 读取与写回

Wiki 是下一项研究的输入，也是本轮新知识的落点。所有阶段沿用**当前任务工作区 `<W>/research-wiki/`**（旧项目使用其已有路径）；插件携带的历史 wiki 和 `archive/` 只读取方法、证明和失败经验，新的研究状态写回自己的任务。新题需要跨轮积累且尚无 wiki 时，由协调者用原 helper 初始化一次；已有知识库直接续用，短题无需造空库。

实际使用前，读取本仓 [Codex research-wiki](../base/skills/skills-codex/research-wiki/SKILL.md) 或 [Claude research-wiki](../base/skills/research-wiki/SKILL.md)。**复用 ARIS 的实体、关系和 helper，不新增 MathRSI wiki schema。** 下表把已有结构接到五个阶段；`wiki-enrich` 用来补已读论文页，不是每次证明更新都必跑的工具。

| 当前阶段 | 先读哪些已有知识 | 什么时候写、写到哪里 | 下一动作怎样消费 |
|---|---|---|---|
| prepare / survey | 导航定位相关论文、旧路线、勘误与失败；读实体中的精确条件及原来源 | 核读原文后经 `ingest_paper` 建 paper，补定理条件、版本、引用与项目用途；新关系用 `add_edge` | specify 将可用进口接入正式规格；route-loop 获得真实可用工具与边界 |
| route-loop | 候选方法的 idea、已做探针、失败域和重试条件，不只看 query pack | 每轮产生实质新判断、反例或路线修订时更新 idea；已完成且判据明确的计算可记 experiment；终轮补齐待同步项 | 先判断失败是否仍适用于当前参数，再决定复用、换线或有理由重试；交 prove 首批义务 |
| prove | 按正在解决的义务检索既有引理、条件、caller、失败及相关 claim 的准确状态 | 可复用引理、反例、固定域排除或接口修正一旦回收就写对应方法／idea 正文，链接完整证明和计算；不等整篇完成 | 将已有结果接进当前证明，跳过已闭同域；尚缺上游条件就派那条连接 |
| verify | 核相关 paper、方法／idea、experiment、claim 所述进口、对象域及既有验证范围 | 实际核验／修复后写准确范围与 `VERIFICATION.md` 链接；proof-checker 自己的 hook 管 canonical claim；直接 Lean／计算检查写普通知识实体 | 局部结论回原 prove；指出准确仍开义务；完整已验结果交 handoff |
| handoff | 读取本次采用结果对应的实体和原验证，确认读者所需范围 | 同步尚未落库的新结论、剩余义务和复现入口；刷新有变化的导航，将当前状态链接进 `NEXT_SESSION.md` | 下一会话沿实体与证据恢复，不重推、重搜已完成且条件未变的工作 |

### 读取：按当前义务找事实，不按轮次重读整库

新会话恢复、进入一个新义务、重选路线或参数／对象改变时，先看 `index.md`、`query_pack.md` 和任务恢复页。它们只用于定位：接着读相关 `papers/`、`ideas/`、`experiments/`、`claims/` 的完整实体，再打开实际要依赖的证明或原运行结果。已有单独的引理手册、失败地图也继续使用，不为了统一结构将它们搬成新目录。

摘要未命中不表示库里没有。以当前问题的异名、引理名、参数或失败条件用 `rg` 搜索该 wiki，再读命中的正文。例如，在 `<W>` 中运行：

```bash
rg -n -i --glob '*.md' '共同选点|joint-majorant|反例' research-wiki/
```

读取必须改变下一动作：前提相同的已证结果直接调用；已完整排除的同一域不换种子再搜；候选仍缺共同选择就派这条义务；对象或条件已改变则重判旧失败的适用范围并说明重试理由。已有失败不是跨参数的永久禁令。没有相关记录或记录条件不适用，就正常继续研究，不要求先写一份“wiki 查询报告”。

### 写入：原 helper 建结构，agent 增补数学内容

当前阶段明确一名 wiki 写入者，通常为该阶段协调者。worker 交回准确命题、条件、证据路径和建议归属；写入者消费后串行更新实体、图及导航。需要让 survey 或 proof-checker 的既有 hook 写入时，将这一段写入交给它并消费其返回，不由多名作者同时重建同一图／索引。无需另造锁服务或写入调度器。

实质结果回收后及时沉淀，包括仍未解决主题的条件引理和有准确范围的失败。若要先处理紧接的关键推导，可先保存在当前报告，随后同步；阶段返回、压缩或暂停前把待同步项写清。没有新增可复用事实时沿用已有路径即可，不机械重建导航。

沿用原结构选择落点：

- **paper**：真实核读的文献、准确版本／定理／条件，使用 `ingest_paper` 建页；原页空缺可由 `wiki-enrich` 补齐。
- **idea／既有方法页**：路线、已证条件工具、候选、反例、失败范围及重试理由。用 `upsert_idea` 建新节点，再增补正文；条件引理的准确状态写在结论处，不能由整页的路线 outcome 推断。
- **experiment**：实际运行及其明确判据、输入域、结果和证据。`add_experiment` 必须显式给 `--verdict`；`yes/partial/no` 相对于该运行声明的目标判断。证明“不存在”的成功排除也可能是 `yes`，不能把所有负实例或排除结果一律映为 `no`。未完成、超时或 UNKNOWN 留在原运行记录和 idea 的开放项，不使用 helper 默认 `no` 冒充数学失败。
- **claim**：沿原 `proof-checker` 真实 audit 的 hook 创建／升级规范节点。直接 Lean 和局部计算检查照样把准确结果写入普通方法／idea 正文、适用的 experiment 和 `VERIFICATION.md`；不为写 wiki 额外启动 proof-checker。图节点状态属于既有登记合同，不决定数学证明本身是否成立。

在 `<W>` 运行命令，**每次 shell 显式使用本克隆 helper**，不依赖作者另一份 ARIS。新路线节点的调用形如（将示例内容替换为实际结果）：

```bash
export ARIS_REPO="/path/to/MathRSI/base"
python3 "$ARIS_REPO/tools/research_wiki.py" upsert_idea research-wiki/ \
  --slug joint-majorant --title "共同对象的联合上界路线" \
  --stage active --outcome pending \
  --thesis "准确的条件结论及其用于原题的方式" \
  --risks "尚缺共同选点；完整证明和反例见 work/joint/REPORT.md"
```

**已有页先读再增量编辑。** `upsert_idea` 默认遇到旧页会跳过，不等于内容已更新；`--update-on-exist` 会重写模板，不能拿它覆盖已经充实的证明／失败正文。`ingest_paper` 的模板重写也有同样影响。保留原字段和证据，直接编辑对应的普通 Markdown 段落及确有变化的合法字段；不要手改自动 `Connections` 或 `graph/edges.jsonl`。遵循原技能的 capture 规则，不把临时额度／环境错误写成数学上的“不可能”。

有新关系时，先确认两端实体存在，再用 `add_edge` 写已核实的关系与准确证据。普通运行的 `supports/invalidates` 边只表示声明范围内的证据，不升级 proof-axis 状态；如旧关系的解释已不适用于新范围，在对应实体保留更正依据，不让下一调用者继续使用过时断言。

正文增补完成后，按原接口刷新并记下本次实际变化：

```bash
export ARIS_REPO="/path/to/MathRSI/base"
python3 "$ARIS_REPO/tools/research_wiki.py" rebuild_index research-wiki/
python3 "$ARIS_REPO/tools/research_wiki.py" rebuild_query_pack research-wiki/
python3 "$ARIS_REPO/tools/research_wiki.py" log research-wiki/ \
  "joint-majorant：补入准确条件结论、反例范围与原证明入口；共同选点仍开"
```

创建节点的 helper 已自动刷新／记录的内容不用再做一遍；上面用于后续正文编辑或尚未刷新的变更。图写入也遵循同一 helper，真实参数见 [ARIS_REUSE](ARIS_REUSE.md) 与技能原文，不发明一个并不存在的 `query`／`update` CLI 子命令。

### 读回并继续：知识需要有消费方

写入者读回**实际实体正文**、新增关系及必要的导航，确认原证明没有被模板覆盖、范围和证据入口正确。query pack 有长度与字段筛选，没列出某条已存引理并不等于没写入；下一动作直接链接该实体，不能只链接摘要。

阶段返回沿已有报告交一句能行动的说明，例如：“`ideas/joint-majorant.md` 已补条件引理 L 和失败域 D；证明见 `work/joint/REPORT.md`；仅缺原输入到共同选点的连接，下一步由 prove 补该连接。”父调用者读该实体及必要证据，采用结果或修剩余义务，不能仅看到“wiki 已更新”就结束。未改动时说明复用了哪份记录即可。

helper 失败时保留已写的数学事实、实际失败原因和待同步路径，推进无依赖工作；不报写入成功，也不因 wiki 故障撤销已成立数学。原恢复页负责当前状态，wiki负责可复用知识，完整证明和运行结果保留在原证据目录；三者互相链接，不复制多套完整研究史。
