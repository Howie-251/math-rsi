# 单题工作区：让下一个行动能接上已有研究

工作区记录正在解决的数学问题。它与 MathRSI 代码版本、可复用领域知识分开；换技能或更新代码，不应覆盖原证明与证据。这里给出一种足够小的起步方式，而非所有任务都必须生成的文件清单。

## 1. 已有项目先恢复，新题再建立

如果目录已有正式规格、恢复入口和 research wiki，先读这些入口，再根据当前义务找到原始证明、程序或计算记录。不要另造一套同名导航、清空 wiki，或以旧报告中的“运行中”判断任务当前状态。需要修改历史结论时说明依据，保留原始记录。

新题先写清原命题与验收。短证明可以只在一个文档中放命题、推导和结论；会跨轮的研究通常需要如下材料：

```text
my-problem/
  FORMAL_SPEC.md           # 原对象、量词、假设、目标与接受的依赖
  NEXT_SESSION.md          # 当前已知、实际缺口、正在运行什么、下一步
  proof/                  # 当前可读论证及必要的局部引理
  research-wiki/           # 使用 ARIS wiki 时按它的实际结构维护
  work/                   # 按具体行动保存输入、脚本、结果、日志
```

目录按需要出现。只有文献任务才维护文献材料，只有计算任务才出现执行日志；不要让启动研究变成准备大量空文件。

五组子流程的具体使用见 [WORKFLOWS](WORKFLOWS.md)。它们交接的是实际数学结果，下面只是新任务尚无命名约定时的默认产物参考；恢复旧项目时沿用原文件与入口，不为匹配本表复制另一套正文。

|进入阶段|默认产物或已有等价材料|后继实际读取与使用|
|---|---|---|
|prepare：specify初步→survey→specify定稿|`FORMAL_SPEC.md`、`LITERATURE.md`、原资料目录与wiki|原量词、参数、允许终点、完整进口条件、基线和待读来源|
|route-loop|`ROUTE_REPORT.md`、实际推导／探针与审阅trace|选定方法、未证条件、首批精确任务和失败证据|
|prove|`PROOF_DRAFT.md`，复杂任务可沿用`OBLIGATIONS.md`，行动目录保存实际证据|已证明什么、如何供给真实caller、尚缺哪些原题连接|
|verify内部assemble|`PROOF.md`或现有TeX入口|从原输入到结论的完整候选；散落论证不再只以文件清单代替连接|
|verify|`VERIFICATION.md`，链接上游真实`PROOF_AUDIT`、独核及按需Lean证据|各检查准确范围、原题状态、具体修复或最终交付条件|
|handoff|`HANDOFF.md`、用户需要的阅读／复现材料、`NEXT_SESSION.md`|读者能查验的结论及接手者可直接执行的下一动作|

八个数学技能由主入口衔接，只有五组子流程；specify、survey属于prepare，assemble属于verify。局部证明或短任务可以在一份正文中保留命题、推导和核验，不为经过每个动作建立空文件。`NEXT_SESSION.md`由当前协调者唯一维护，worker回交新增事实与证据位置；wiki按原结构持续更新，不只在交付末尾补写。

使用 ARIS `research-wiki` 时先读本仓相应宿主的完整技能及 base/tools helper 说明，由它维护原有图结构和知识条目；这里不重新规定另一套 wiki schema。本仓已带该技能与 helper；运行依赖异常时先保存普通 Markdown 事实，修好实际调用后同步，不能声称失败的 helper 已执行。

自动生成的 `query_pack.md` 是导航，不保证收入全部已存事实。本次实际试用中，positive idea 的 Thesis/Key risks 已写入实体页，却没有进入自动摘要。恢复时按当前义务读取相关实体页，在 `NEXT_SESSION.md` 直接指向关键结论、条件与未闭义务；写入后读回相应实体即可，不必为此修改上游 helper 或重复整套研究。具体行为见[独立试用](../development/propertyb-rebuild/forward-use/REPORT.md)。

## 2. 正式规格要让两个人读出同一个问题

写明原对象是什么、量词覆盖哪里、给定哪些参数和假设、目标允许哪些解答。把新加的技术条件放到候选引理里，不偷偷加到原题里。

例如“找到一个满足约束的矩阵”只要求一个可靠见证；若同题允许证明不存在，则另一终点必须覆盖原始全域。二者可以共用检索与程序，但验收不是同一个布尔字段。“给所有超图证明可染”也不同于“给这一个超图找到染色”。

文献定理、已证明结果、暂时接受的进口、尚未成立的候选分开说清。需要用户决定的关键歧义尽早提出；其余可依据上下文做合理约定并继续独立工作。核心数学定义值得用一两个边界例子反译确认，而不是每次都全面重读原题。

如果已有原规格，保持其文件名与入口。新题建立自己的规格，不能把旧结论改写成新任务状态。

## 3. 把研究行动写到能执行的程度

Root 选择下一项行动时，用自然语言回答五件事即可：当前缺什么；准备做什么；输入与允许假设是什么；产物将如何改变整体证明；给多少资源、什么情况停止。简单行动一句话足够，昂贵行动才需要更具体的规模和预算。

下面是格式示例，不是已完成的数学结论：

```text
义务：证明所有实际输入都能选到引理 L 所需的结构。
已知：L 的条件结论已核对；当前仅缺选取，不缺数值表。
行动：尝试用同一原对象的总量约束证明选取，保留失败配置。
交付：选取引理及原输入调用，或具体说明哪一步不能成立。
预算：本批有界推导；若仍只得到局部改善，回到其它表示比较。
```

多个结论需要同一组选择时，应在这里声明共同对象和坐标。否则几个各自正确的代理结果可能无法合并。代理需要相关文件和明确写入范围；不需要整段无关对话历史。

命令和耗时记在行动目录中；证据文件很大时保存复现入口及实际存储位置。需要能找回支撑论断的输入和输出，不要求每轮重新复制所有材料。

路线或证明中出现新的术语、遗漏进口或反例问题，带当前式子、已查来源和具体疑问调用survey，收回原文条件后回到同一义务。verify若只验证一个引理，返回原prove调用点；已有完整证明则直接verify。改变核心对象或方法才回route-loop，不因每个索引错误重做整个准备阶段。

## 4. 恢复入口应短于完整研究史

`NEXT_SESSION.md` 让接手者知道原目标、当前可信结果、具体未闭义务、在途进程／代理与下一项行动。完整证明与失败历史通过链接找到，不复制到每份导航。

```text
原题入口：FORMAL_SPEC.md。
已成立：引理 L（证明与证据位置）；固定域 D 的排除（准确条件）。
尚未闭合：任意原对象是否都进入 D；另一条路线 A 当前独立开放。
近期判断：停止扩大局部表，因为它未保留共同约束 C。
值得重试的条件：证明 C 的新连接，或发现当前必要模型可进一步收紧。
在途任务：没有／具体进程、代理、产物目录与实际状态。
下一步：明确待解决问题和首先应读的文件。
```

有重大结果、反例或路线改变就更新。持续研究应定期整理，但不为定时器额外编写汇报。用户的 Goal、暂停、预算约定由实际宿主和任务管理；文档中的“继续”不是重启 Goal 的授权。

停止时区分：任务完成、该范围已闭、当前路线无新增信息、资源耗尽、缺依赖、用户暂停。计算预算耗尽可以在得到相应资源后继续；已完整扫过的同一域不能仅换种子重跑。未完成永远不因时间耗尽改写成完成。

子流程的局部轮次或探索预算用尽，先把真实结果和下一动作返回调用方。它不自动改变Goal状态，也不阻止其它独立的已授权工作；整个Goal的暂停、总预算和恢复按实际用户指令与宿主状态处理。

## 5. 提交可检查的解答

自然语言成稿用定义、定理／引理、证明组织。每个假设写在结果处，每个引用指向实际版本与定理或公式。正文接通原问题；必要证明不能只散落在未说明的 MD 链接后面。

计算证据随同说明实际输入、遍历范围、完整性依据和复核命令。Lean 项目给原题声明、实际构建目标、固定依赖与审计入口；默认 build 成功不自动说明构建了所需新主定理。跨模型意见另列实际阅读与执行范围。

需要分享时调用 ARIS `render-html` 或合适的文档工具，把完整可读故事整理成一份入口，再提供深层源码。对外呈现贡献与证据，不用内部纠错日志淹没正文；原日志仍留作查验。是否需要 PDF、HTML、Lean 或大型证据包由任务决定。

## 6. 用哪个版本、怎样更新

任务起步或切换版本时记录 MathRSI 提交与启用的插件，ARIS 技能按实际来源记录。开发中的未提交内容如实注明；不凭目录名字伪造版本绑定。

工作区可以位于仓库外，通常正是原研究目录。若临时放在仓库的 `workspaces/`，它默认不进入代码 Git；重要研究资料仍须按自己的数据保存方式保留。`.gitignore` 不是备份。

需要给通用流程提改进时，记录触发问题、建议行为和可检查例子，再到 MathRSI 的开发分支实施。单题使用过程中不自行改变核心完成标准。关于插件如何交流见 [协作约定](PLUGIN_CONTRACT.md)。
