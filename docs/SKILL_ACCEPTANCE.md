# MathRSI 技能怎样验收

本次实际阅读了 ARIS 固定提交 `c485faa59a68e51c6575dea67ca57abc7a6a2b9c` 的 [CONTRIBUTING](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/c485faa59a68e51c6575dea67ca57abc7a6a2b9c/CONTRIBUTING.md)、技能目录及 [auto-review-loop完整Codex实现](../base/skills/skills-codex/auto-review-loop/SKILL.md)。用户指定后者作为详细程度范例，其548行包括运行恢复、实际review调用、原文留存、修正与复核、失败和退出处理。

ARIS CONTRIBUTING明确要求技能frontmatter、完整指令、更新文档、在宿主实际试用并验证行为；它没有规定最低行数。本项目用户额外要求详细、可执行的散文工作流，反对几个SOP口号或仅列别的技能名称。两者一起执行：不靠篇幅凑数，也不以“渐进披露”为理由把关键内容删掉。

## 内容必须支持一次真实工作

入口首先说明哪些请求属于它、需要哪些输入和已有状态、何时读取哪个实质reference。中段解释怎样判断与行动：哪些条件允许用某定理或工具，怎样准备真实输入，输出如何用于下一步，错误或停滞时改变哪条假设/表示/路线。结尾说明可以得出什么结论、仍欠什么连接、如何恢复及交接。复杂步骤应有来自真实项目的完整例子。

这些内容可以分层存放，但下层必须实际存在。Property B的L1–L117库存、signed门、一般k完整证明、失败反例、计算与Lean操作指南以及已有检查器均随仓库保存；source-map仅负责定位，不代替内容。现行指南不能要求读作者另一台机器的文件夹来补全关键数学。

一个独立技能应有可单独完成的任务。文献查漏、推进一个下界、验证一条计算证明链分别有不同输入和工作成果，因而拆为三个Property B技能；“检查是否正确”这样的同义目录不值得另造一层。通用spec和strategy仍在总控，复用ARIS formula-derivation/proof-writer等，不为增加技能数造空壳。

## 具体核查怎样执行

格式检查验证新技能名称/frontmatter/未完成模板。文件和资源检查确认所有现行入口能解析到本仓，双端原技能保留各自资源与helper依赖；相对发现别名在搬迁后仍指本仓。原始历史资料的旧日志/展示引用另作快照说明，不能篡改原文来伪造全历史零断链。

功能试用由未参与写作的agent读技能和真实输入，在独立副本执行。检查它是否找到正确工具、保持原题参数、判断失败含义、消费实际输出并接回完整命题。一个简单算例答对不足以验收完整能力层；因此本轮另有真实ARIS helper调用、六/七元证书、明确signed反例、无收益component路线与十二元已有独核范围。

跨模型审阅针对明确版本与疑问：是否仍有能力断层；数学工具条件是否丢失；实际caller与目录是否连接；运行案例能否搬迁；是否把历史候选升级成已证。保存原始回应与读取/执行范围，逐项修真实问题。共同作者Gemini的反馈与独立Grok意见分别记录，不把“同意”作为数学核验。

本地测试采用项目内完整源和隔离工作副本，无需覆盖用户全局skills。外部模型、Lean/Mathlib、网络SDK、TeX仍按真实环境使用；未测服务不写已就绪。新方法的通用提速或RSI效果需要另外的研究评测，本轮不作该项宣称。
