# MathRSI 技能怎样验收

本次实际阅读了 ARIS 固定提交 `c485faa59a68e51c6575dea67ca57abc7a6a2b9c` 的 [CONTRIBUTING](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/c485faa59a68e51c6575dea67ca57abc7a6a2b9c/CONTRIBUTING.md)、技能目录及 [auto-review-loop完整Codex实现](../base/skills/skills-codex/auto-review-loop/SKILL.md)。用户指定后者作为详细程度范例，其548行包括运行恢复、实际review调用、原文留存、修正与复核、失败和退出处理。

ARIS CONTRIBUTING明确要求技能frontmatter、完整指令、更新文档、在宿主实际试用并验证行为；它没有规定最低行数。本项目用户额外要求详细、可执行的散文工作流，反对几个SOP口号或仅列别的技能名称。两者一起执行：不靠篇幅凑数，也不以“渐进披露”为理由把关键内容删掉。

## 内容必须支持一次真实工作

入口首先说明哪些请求属于它、需要哪些输入和已有状态、何时读取哪个实质reference。中段解释怎样判断与行动：哪些条件允许用某定理或工具，怎样准备真实输入，输出如何用于下一步，错误或停滞时改变哪条假设/表示/路线。结尾说明可以得出什么结论、仍欠什么连接、如何恢复及交接。复杂步骤应有来自真实项目的完整例子。

这些内容可以分层存放，但下层必须实际存在。Property B的L1–L117库存、signed门、一般k完整证明、失败反例、计算与Lean操作指南以及已有检查器均随仓库保存；source-map仅负责定位，不代替内容。现行指南不能要求读作者另一台机器的文件夹来补全关键数学。

一个独立技能应有可单独完成的任务。文献查漏、推进一个下界、验证一条计算证明链分别有不同输入和工作成果，因而拆为三个Property B技能；“检查是否正确”这样的同义目录不值得另造一层。通用数学层则按实际工作拆分：总控选择入口和消费产物；prepare组织specify初步、survey及specify定稿；route-loop拥有方法审阅、实作探针与修订循环；prove执行证明、计算和回收；verify内部按需assemble，再执行真实proof-checker、独核和按需Lean；handoff整理交付及持续知识。不是把每个动词都做成技能，也不再把这些实质流程都藏在总控的一段约定中。

新结构的职责和使用顺序见 [WORKFLOWS](WORKFLOWS.md)。九项解题技能（八项子技能加总控）保持原职责，另有独立外层维护技能 [mathrsi-meta-evolve](../base/skills/mathrsi-meta-evolve/SKILL.md)，合计十项 MathRSI 技能。内部复用ARIS完整实现：直接可用的动作按其实际合同执行；数学对象、目标或输入形态需要适配时，明确交代转换、返回位置及原题保真。不能把一个ARIS技能名写在表格里就称已经完成集成。

## 具体核查怎样执行

格式检查验证新技能名称/frontmatter/未完成模板。文件和资源检查确认所有现行入口能解析到本仓，双端原技能保留各自资源与helper依赖；相对发现别名在搬迁后仍指本仓。原始历史资料的旧日志/展示引用另作快照说明，不能篡改原文来伪造全历史零断链。

功能试用默认由当前协调者或具体作者读取候选技能和真实输入，实际执行受影响的调用；子代理协助具体实现、调试和核对。不把“无历史 agent 独立跑完整流程”设为技能使用、改版或接纳的强制前置。真实疑问、用户要求或风险需要时再安排有界独立消费；数学正确性所需的独核仍按原题合同完成。检查实际工具、原题参数、失败含义、输出消费和下游连接，不为一个局部修改重跑无关整题。此前已执行的ARIS helper、六/七元证书、signed反例、component止点与十二元独核，各自保留原范围。

子工作流试用还需覆盖它拥有的真实转移。例如prepare能从初步问题做外部查漏、核原文并定稿，而非只生成模板；route-loop收到审阅后实际做区分性推导／探针并修改路线，而非重复征求意见；prove收回条件引理后检查caller并推进下一项，而非只汇报；verify将局部义务返回原prove、将实质缺口保留为未证，并消费上游checker真产物；handoff保留数学与展示／复现的不同状态。主流程再用现成产物测试跳过入口与同轮衔接，不能要求每个任务从零跑满所有阶段。

恢复测试关注是否从真实断点继续、复用未变结果、避免重复写canonical报告。route-loop或prove中的定点survey应带新问题返回原义务；局部预算耗尽不能自动暂停整个Goal；服务故障不改写成数学失败，也不能生成虚假审阅PASS。数学正确性按证明和实际验证判断，没有路线评分真值门。

跨模型审阅针对明确版本与疑问：是否仍有能力断层；数学工具条件是否丢失；实际caller与目录是否连接；运行案例能否搬迁；是否把历史候选升级成已证。保存原始回应与读取/执行范围，逐项修真实问题。共同作者Gemini的反馈与独立Grok意见分别记录，不把“同意”作为数学核验。

本地使用采用项目内完整源；只有路径搬迁、写域隔离等真实需要时才建工作副本，无需覆盖用户全局skills。外部模型、Lean/Mathlib、网络SDK、TeX仍按真实环境使用；未测服务不写已就绪。新方法的通用提速或RSI效果需要另外的研究评测，本轮不作该项宣称。

实际结果见 [VALIDATION](../development/VALIDATION.md)，细分阅读与运行记录在 `development/propertyb-rebuild/`。

本次新编排的设计依据另见[两题实证转折](../development/workflow-redesign/REAL_PROJECT_TRANSITIONS.md)。历史项目“曾这样完成某个义务”支撑为什么设计该返回动作；它不等同于新技能已在当前宿主重新走完同样任务。验收报告分别列出历史证据提炼、本轮结构／接口检查、真实行为试用及未测部分。

格式、相对链接和helper `--help`通过只说明相应结构或调用接口有效。新增子流程的联网检索、外部reviewer、proof-checker完整修复循环、Lean及长程行为若未实际试用，分别列为未测；旧Property B案例和ARIS副本smoke的成功不自动迁移成整套新编排已验收。开发报告应记录当前真实文件版本、实际输入、执行范围、产物和仍未验证的分支。

## 外层维护技能的使用验收

版本演进的执行链只在 [mathrsi-meta-evolve](../base/skills/mathrsi-meta-evolve/SKILL.md) 维护，[人读入口](EVOLUTION_WORKFLOW.md)提供调用说明。先完成并集成技能，再由协调者实际读取它，用已有研究 context 推进具体维护；不能先在技能外做完新版，再追写成该技能的运行。取证、真实 diff、讨论处置、实际使用与采用范围留在同一维护记录。

入口与别名集成可核链接和当前路径；修改命令就运行受影响命令；修改研究行为就观察实际决定与后继动作；仅新增历史例子不重跑旧大型研究。复用未变检查，不为每次文字调整重启整套审阅。未测服务和尚未执行的行为按真实状态记录；[v2本轮记录](../development/evolution/dd-v2-20261102/EVOLUTION.md)给出具体实现、使用与审阅范围，本说明不代替实测。
