# 从研究经验到下一版 MathRSI

本流程消费真实研究和使用中暴露的问题，把有根据的经验变成可审阅、可试用的插件或base改动。它是独立维护工作，位于图1的“Research experience → Distill · Review · Evaluate → next base”；不是五个解题子流程中的第六阶段，也不在每次handoff后自动启动。`base-v2`表示后续迭代方向，本流程不自动创建该版本、发布或推送。

一次维护应走通：获得维护范围 → 读原始使用证据 → 提出准确行为变化 → 修改实际调用文件 → 针对性审阅 → 独立使用者实际试用 → Root消费结果并修订、拒绝或纳入 → 交待版本与采用时机。短改动可以在现有维护记录和一个补丁中完成，无需另造平台、统一JSON或一套空报告。

## 进入：维护授权与真实输入

由用户要求维护、开发任务的既有授权，或Root在已授权开发范围内接收一条具体问题时进入。原研究只授权解题时，先把经验留在任务wiki与恢复记录；不能据“值得改进”就修改MathRSI核心、扩大模型调用或恢复暂停Goal。已有授权足以覆盖的维护继续执行，不重复请求同一许可。

Root先读 [AGENTS](../AGENTS.md)、本轮维护要求及相关任务的原规格、run/checkpoint和wiki实体，再沿证据找到真实输入、调用任务、源文件、原始回应、命令和结果。`query_pack`只作导航；重要条件可能只在实体正文中，见 [WORKSPACE](WORKSPACE.md)。资料缺失时记准确缺项，不用事后总结补成没有发生的操作。

维护输入应让另一人看见“原本想做什么、实际做了什么、哪里不符合需要”。可以是一条重复派发记录、局部验证误送全局交付的调用、一个失效参数、遗漏条件的来源，或真实运行暴露的成本。单纯觉得文字不够漂亮不等于需要重构；已有正确表达直接保留。

Root读完后先决定这是什么变化，避免把不同层次混在同一补丁里：

- **单题状态或数学结果**留在该任务工作区。新引理、反例、未闭义务及其证据先更新原wiki；维护文档不把候选变成已证，也不重新认证旧数学。
- **可复用领域知识**进入对应插件。保留完整前提、结论、证明或失败输入、实际caller和重试条件，由领域owner核对；具体合作见 [PLUGIN_CONTRACT](PLUGIN_CONTRACT.md)。
- **通用调用或研究行为**才考虑base，例如阶段返回、审阅边界、结果回收或恢复。说明它解决什么真实问题，以及为何不能仅修本题记录或领域接口。

同一经验可以同时产生一项领域条目和一项通用改动，但分别写清依据与影响。没有合适的通用结论时，只保存准确实例也是有效维护结果。

## 提炼：把经验改成可检查的行为

在现用维护记录写清触发输入、旧行为、拟改行为和可观察的区别，再指向原始证据。例如“局部verify通过后，结果应回原prove的L3，而不是启动全题handoff”，比“加强回流”更能指导修改和试用。

明确实际受影响的caller、被调用技能、返回产物和消费处。多份文件表达同一契约时，Root协调其共同修改；ARIS原技能、helper与桥接按本仓固定副本及 [ARIS_REUSE](ARIS_REUSE.md)读取，不能只改说明而让实际调用继续执行旧合同。需要改变上游副本时另列准确范围，不静默改写来源快照。

同时说明哪些旧证明、checker或接口仍有效。数学目标、量词、允许进口与验收不因提高效率而改变；新策略若只证明更弱或附条件的结论，仍按原义务开放处理。维护不能把一项未完成的验证删掉后称作提速。

Root为改动安排短期开发分支；并行作者只有不重叠的文件或模块写域。当前已有合适分支与维护记录就复用，必要时才建worktree。先核当前工作树及他人在途写入，保留用户未提交内容，不为维护重置或清理原研究。

作者读取对应技能与真实接口后修改可执行指令、调用示例和返回消费；只改受影响范围。接线或参数问题先验证真实接口，行为问题则准备能暴露旧错误的原输入。不要用大量新文件、评分字段或Python调度器代替这份具体补丁。

## 审阅：针对设计与接口，保留实质对话

改动形成可读补丁后，按当前维护授权、项目要求及真实服务能力选择reviewer。Codex读取本仓 [research-review](../base/skills/skills-codex/research-review/SKILL.md)，Claude读取 [同名主线](../base/skills/research-review/SKILL.md)，并执行所需backend、independence及trace契约；调用细节见 [REVIEWER_MCP](REVIEWER_MCP.md)。不固定要求每项改动都双模型或整卷重审。

这次明确执行research-review的**数学工作流维护适配**：检查原题保真、调用边界、接口、证据消费和恢复行为。传入真实旧输入、修改文件、原ARIS合同、diff及待解决问题；让reviewer读原件，不只看作者总结。显式传 `— composed: <现用维护记录绝对路径>`，由Root或指定唯一writer合入返回，保留原始prompt、response、session及实际阅读/执行范围。

`composed`只改变报告归属。调用任务还须明确替换原Step3的ML实验、论文outline和投稿claims产物：返回具体失效路径、可核的接口条件及最低补证/试用动作。Step4以本轮设计疑问和受影响调用已判断清楚为返回点，不等论文叙事或双方共识；reviewer不另派作者、探针、下一轮修法或同级解题阶段，修法由本次维护owner负责。

必要的同会话证据追问、反驳与修订复核照常执行。Root将原意见对照原件：真问题落实到文件或试用，误读则给具体证据回应；双方判断分别保留。收到“认可”不等于行为已验，服务失败、未读文件或超时也不算接受。保存可恢复的会话与未决问题，继续不依赖它的工作，不自动重发付费调用。

若补丁改变了reviewer指出的关键逻辑，带实际diff和新结果回其原session定向复核。未变材料复用有效意见，不为凑审阅轮数反复发送。独立数学验证仍按对应义务完成，设计审阅不替代证明、覆盖或算术。

## 试用：让没有写补丁的使用者实际执行

Root把原始问题或中断状态、必要输入、候选版本、任务授权和独占输出位置交给未参与该补丁写作的agent。给它完成任务所需的真实材料，而非只要求“确认修法合理”；不要在输入中代写它应该得到的运行结论。任务很小时直接给原问题与必要路径，不要求另建CONTEXT、manifest和一组回执。

使用者读取候选技能后，实际走受影响的调用路径，交真实产物、错误、停止点和下一消费者。涉及计算就执行对应的有界命令并读结果；涉及模型行为就实际调用已授权reviewer；只做静态阅读则按静态消费审查报告，不能用它关闭尚未执行的行为疑问。宿主没有所需能力时准确留下未测范围。

局部返回改动至少要看到“子调用完成 → 父读取产物 → 父执行正确下一动作”；恢复改动要从给定真实断点继续；路径/schema改动要用当前副本和真实参数调用。测试不要求从零重走五个阶段，也不默认重跑旧数学、全表、Lean或外部服务。只重核受改动影响的属性，复用仍有效的证据。

成本只测当前判断需要的部分，例如重复调用是否消失、实际墙钟/CPU/内存、序列化和读回负担，连同输入规模与命令保存。没有成本比较就不宣称提速；一个有用改动也不必提供新的性能分数。已知答案的开发案例可验调用行为，但不能冒充盲测、通用解题率或RSI增益评测。

Property B和ECC的仓内原交接可作为有界消费场景：检查同一输入下是否保持原量词、进口、共同对象和返回位置，或在独占副本执行已经授权且依赖齐备的具体实例。ECC使用 [已收录交接](../development/context/ecc-source/README.md)，不因领域标签自动加载草案插件、访问原工作区或恢复原研究。跨域影响要用相关材料检查，不强制两领域都完整解题。

独立使用者交付后，Root立即读实际文件、命令、原始输出和未闭项，确认结果回答了提案所针对的问题；不能只收一句“PASS”。同家族使用者独立于作者不等于跨家族审阅，按真实身份和检查范围报告。

## 消费：修正、拒绝或纳入

Root把试用事实与提案中的行为差别逐项对照。修法有效且原契约保持，就纳入本次维护范围；若只修了部分路径，缩小声明并补剩余的具体动作；若引入更多重复、错误返回或无证据的收益，就修改或拒绝。拒绝时保留输入、失败与重试条件，不删除负结果，也不无限包装同一提案。

真实错误由对应文件owner修复，再让使用者重走改变的那一段；关键设计变化按需回reviewer复核。已通过且未受影响的数学和工具结果直接复用。连续两轮仍没有新增证据时，Root接管具体缺口或重新缩小提案，不以继续讨论代替执行。

当前未测依赖若正是提案的关键行为，准确记“待试用”，不能写成全面纳入验收；不受它影响的有效改动仍可按准确范围交付。记录里分别保留设计意见、静态检查、实际行为、成本和数学验证的范围，不合并为一个万能PASS。

## 两个已有修复怎样提供输入与验法

**`composed`不自动替换Step4。** 原始输入是route-loop调用完整research-review和原件中“双方共识／论文叙事”终点之间的冲突。Grok具体指出只传组合信号仍会让内外都推进修法，原意见及Root处置见 [审阅处置](../development/review-loop-integration/REVIEW_DISPOSITION.md)。维护产物是在真实调用任务中明确适配Step3/4、保留证据对话，并把fix和下一轮交回route owner，而非删除research-review的实质职责。

这个例子的接口依据可直接对照 [RR原件](../base/skills/skills-codex/research-review/SKILL.md)与 [route调用任务](../base/skills/mathrsi-route-loop/SKILL.md)。已有Gemini修订静态复核和四情景消费者阅读支持其当前描述，**没有实跑完整A–E修法循环**。若维护的是该行为，使用者应在有界原始路线问题中实际收回审阅、执行修法再复核，查看谁派发和消费；不能拿已有MCP连通成功代替这条行为试用。

**局部verify返回原prove。** 输入是一项已知双配额引理及其下游caller，不是全项目完成证明。改动要求局部验证只关闭其scope，父prove读回后继续最后的原目标连接；已有 [真实行为试用](../development/workflow-redesign/behavioral-trial/REPORT.md)保存原问题、完整正文、精确计算、fresh同家族意见和CALLS。

该试用实际看到了实例成本1、错误叠加2、容量修复后1，局部verify返回后原prove完成下游；没有跳到全题handoff。它支撑这一条具体转移，未执行正规proof-checker、Lean、联网调查或完整路线循环。新的维护可复用这条有效证据，只有改变该路径时才重走受影响部分，不能将历史试用称作本文新流程已运行。

## 版本、提交与研究何时采用

维护收束时在现用记录写清实际补丁、证据、Root决定、未测范围与采用条件。按本次本地开发授权提交已接纳且可审阅的变更，记录真实提交和分支；尚未提交就如实记工作树状态，不能以目录名或图中的v1/v2假造版本。保留用户其它未提交内容，不随本流程推远端、发布或修改全局技能配置。

任务起步按 [WORKSPACE](WORKSPACE.md)记录MathRSI版本与启用插件。在途研究不因为本地有新提交就自动换指令：由其协调者读维护处置，确认当前义务是否受影响，记录采用版本、切换点和需重核的具体结果；随后从原断点继续。新任务可采用已接纳版本，候选分支只在明确试用范围使用。

切换版本不改变原目标及验收，不抹去旧审计，也不要求无关成果重验。若无法完成关键行为试用，交接明确pending与下一动作；本次维护完成、某个补丁接纳和数学题完成是三种不同结论。

## 可复制的维护请求

```text
读取 /实际路径/MathRSI/docs/EVOLUTION_WORKFLOW.md并执行独立维护。
本次授权：在本地修复 <具体行为>；不推远端、不恢复原数学Goal。
原使用输入、run/wiki与原始证据：<实际入口>；现用维护记录：<路径>。
先判断这是任务状态、领域知识还是base调用行为，写明旧/新行为与影响面。
由Root协调短期分支和独占文件，修改真实caller、子技能与返回消费。
按当前宿主research-review做针对设计/接口的数学工作流适配：显式composed，
Step3返回具体条件/最低试用，Step4在本轮问题清楚后返回；保留原件对话和原文，
修法只由维护owner调度，不运行论文共识或另起解题循环。
让未参与补丁写作的agent从上述原问题实际走受影响路径，交真实产物、
成本/错误与准确未测范围；Root读回后修正、拒绝或接纳。
复用未变有效证据，保持原目标和验收；最后记录本地提交或真实未提交状态，
以及研究工作区何时采用。产物写入现用维护记录与补丁，不另造一套报告树。
```

本文提供维护的可执行入口；其两例是已发生修复的证据，不宣称本文发布后已完成一次新的演化运行。实际开发和未测范围继续在 [VALIDATION](../development/VALIDATION.md)及相应维护记录中报告。
