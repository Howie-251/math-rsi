# 全局进展重评：规约以后，原题真的更容易了吗？

本协议由 [mathrsi-research](../SKILL.md) 的唯一研究调度者执行，贯穿五阶段。各阶段在派批、收件和安全返回处识别触发，沿直接 caller 上报；不新增第六阶段，不让 reviewer 接管作者队列。独立调用子技能且没有上层时，当前执行者负责其获授权范围内的决定，范围外只回交建议。

**规约成立与规约有用必须分别判断。** 数学上等价的问题可以一轮轮换表示，但未必更容易解决。母对象更少而扩张空间更大，多个局部谓词变成一个同样难证的联合引理，或把难点移到分类完整性、证书生成和回接原题，都不能仅凭“又有新规约”继续加码。保留正确成果，同时判断是否值得把下一批资源押在它上面。

## 1. 每批前、收件后：先看原题的剩余路径

恢复时读原规格、当前剩余义务、最近实际结果及有关 wiki 实体。不要只看当前小引理的成功摘要。用现有义务名或一句话固定正在处理的原题瓶颈，例如“任意原 H 能否选出满足共同条件的结构”；不另造 ID 系统。改脚本名、引理名、参数分块、worker 或中间表示，仍追踪同一个数学障碍，不能重置其历史。

派发一个实质批次之前，说明它成功、失败或得到不确定结果后，分别会改变哪个决定。一个批次是围绕同一问题完成一次推导／探针／作者任务并消费结果；不是一条消息、一份文件或一个并行 worker。并行任务同为一次决策服务时合并看；单个长批次也必须有中途可检查的范围或资源边界，不能把整个未知研究称为“一轮”以逃避回看。

收件后在原路线报告或证明记录中写清以下三件事，短任务几句话即可：

- **之前缺什么，现在少了什么。** 原输入到原结论的哪条假设已供给、哪个完整分支已关闭、哪个错误方向被实际证据排除，或哪项关键不确定性已消除并改变下一行动？局部待验结果与已经可用的证据分开。
- **即使这个局部任务全部成功，还差什么。** 列真正剩下的连接、全称覆盖、联合相容、实现与验证，不用“之后装配即可”掩盖尚未证明的数学。某个较弱结果已足够时立即消费，不继续追更强版本。
- **接下来为什么更可行。** 说明新的可调用定理、可承接的有限域、更小的真实联合空间、更低的端到端成本，或有决定价值的下一探针。若只有表达更整齐、局部数字更漂亮，就记“局部产物增加，原题瓶颈未变”，不能写成原题完成百分比。

对规约尤其要比较**规约前后**：原目标与允许解答是否保持；原来和现在还需证明什么；原对象数乘以每对象后继扩张后究竟有多大；需要多少生成、运输、存储、读回、独核及原题连接工作。数据未知就指出未知并先做有界成本探针，不编造 token、耗时或成功率。没有数值估计的解析路线也可有实质收益，例如接上已有可用定理、消去一个真实假设；要给出具体依据。

有用的负结果同样算进展：严格反例使过强引理退出队列，或一个探针决定应改变共同表示。相反，同一种失败反复出现而任务仍原样续派，不因每次记录不同就变成新的决策信息。闭合一项真实必要子义务也有价值，不要求每批消去全题最难的一环；须说明它解决了规约前哪个已有障碍或接口风险，或给出可调用工具、真实域／完成成本的改善。仅证明新规约内部的转换或包装自洽，却未给原缺口提供新依据，不计原题决策增量，不能不断自产外围义务来刷新进度。

## 2. 何时必须启动独立全局重评

满足下面任一项，必须先重评，再批准受影响路线的下一批扩张。Root 自己写一句“还有价值，继续”不能代替这个动作。

1. **同一原题瓶颈连续两个实质批次没有决策增量。** 包括每批都有新规约、局部表或条件引理，但关键未闭连接、实际覆盖或可完成的总成本均未改善。按数学内容累计，换名、换代理或切换阶段不清零。
2. **局部成功已经暴露全局脱节。** 发现即使当前任务全部成功，仍留下原来的核心难题，且没有证据说明新接口使它更可处理；或局部最优项不活跃、分别规范化不能共同实现。明确看见这种失配时不必等第二批。
3. **准备扩大未经评估的投入。** 从探针扩到全域扫描、增加一个扩张维度、成倍铺开作者／证书／形式化模块，或预计超过原先批准的本批资源。必须先核端到端收益与剩余义务；已经评过的完整计算计划内正常分块不重复触发。
4. **关键依据发生改变。** 核心归约被反例击穿、需要的共同选择不成立、公开基线使竞争队列失去意义、实际成本推翻原可行性估计。固定的用户目标不由此擅自改变，调整的是受影响方法与任务。
5. **到达预先约定的全局检查点。** 连续研究启动时就写具体批数、主动工作时间或计算范围；没有更适合的任务约定时，默认同一路线三个实质批次后在安全返回处重评，即使每批各有新推导。时间边界到达后不再派新任务，正在执行的有用不可分命令在安全点收回。检查点可由已评过的有限完成计划替代，不能写成“等有空”或事后不断顺延。

短证明、单次可完成的局部修复直接完成。完整候选已经足够进入核验时，直接推进必要 verify，而不以重评延误交付。长期准备、审阅、形式化和包装同样会空转：未变原件反复审、用排版填补数学缺口、已经满足交付仍继续美化，都按同样规则判断；并非只有 prove 才能触发。

## 3. 先收束旧队列，再给两位独立评估者完整视野

触发后停止新增受影响路线的扩批、同域重复任务和无依据展期。保留已得合法引理、数据和失败记录。查询真实在途状态，完成的立即收回；有用的不可分计算安全完成或留可恢复断点，不按“停滞”标签直接杀进程。确实无用的任务由其 owner 安全收束，不能关别人的会话。无依赖的其他义务可继续。

唯一调度者准备一份短包，放在现有报告的一节或本次行动目录，原件通过路径提供：

- 原题完整对象域、量词、允许终点和用户预算；原规格入口。
- 当前整条路线、已闭和未闭依赖、瓶颈及最近重评决定；不能只交局部成果列表。
- 最近两批的实际输入、规约前后、原始输出／失败、相关 wiki；未知和待核证据明确标出。
- 累计及预计剩余模型、计算、I/O、复核和集成成本，真实在途任务；没有测量的项照实说明。
- 当前备选方案、仍有意义的直接构造／反例路线和现成较弱必要门。没有可用备选就说明，不为凑路线虚构。

默认实际启动 **两位独立只读评估者**，先分别返回，不先给他们看另一人的结论：

**A：原题连接与反事实。** 从原题重建当前完成路径，核局部成果到底关闭了什么。必须回答“假设当前局部任务今天全部完成，还剩哪几项数学义务；其中最难的一项是否只是被移了位置？”指出判断所依据的实际原件，不能只复述作者的进度标签。

**B：路线选择与总成本。** 比较继续当前方法、补真实输入连接、恢复共同约束、换表示／较弱必要门，以及原题允许的直接构造或反例机会。比较完整完成路径，不只比较小内核运行时间。给一项最值得做的下一动作及它能改变的决定，不要求现场解决整道题。

优先使用可用的、未参与当前局部作者工作的会话；不能把同一作者换个角色名当独立视角。原生工具支持时用新 agent 且不继承整段局部对话，只给上述必要原件。跨模型按当前用户偏好与已有服务使用；不同 native agent 仍如实标 same-family，不冒充数学审阅通过。若原审阅者刚完成完全相同范围的独立全局判断，可复用其原回应，不为了人数重复调用。

只在两者对承重事实、可完成成本或主要路线有实质分歧且现有证据不能裁定时，增加第三位处理那个具体分歧；不默认开三个模型争取一致。评估限定为一轮只读分析，明确所需源文件和回复范围，不自行搜索新领域、开大计算或启动 proof-checker。确缺决定性材料时指出具体缺件，Root 补证或执行一个有界探针即可，不层层加 reviewer。

可复制派工（把路径、角色与本轮边界填实后，调用宿主实际启动工具）：

~~~text
你是本次独立只读全局评估者 <A：原题连接 / B：路线与总成本>。
原题与允许终点：<规格路径>；整体依赖与当前瓶颈：<报告节>。
触发原因：<两批无决策增量/规约脱节/扩批/依据变化/检查点>。
实际规约前后、两批证据与wiki：<路径>；成本与在途：<路径>。
请读原件，评估原题完成路径，而非只改当前小引理。
必须回答：本轮真实推进了什么？局部工作即使全部成功还缺什么？
规约是否减少了实际数学障碍或完整执行成本，还是只转移了它？
建议一个优先动作：有界继续、补连接/换表示、转路线、装配核验、收束分支。
给证据定位、该动作的输入与预期决策信息、停止/重评条件；未知明确保留。
只返回本次报告，勿改源文件、跑研究计算、启动作者或等待其他评估者共识。
本次一轮只读，最多指出一个影响决定的缺件；已有资料足够就直接判断。
~~~

在有 `collaboration` 的宿主，新评估任务用 `spawn_agent`；空闲旧 agent 开始下一项用 `followup_task`，`send_message` 只补信息。MCP 按 [REVIEWER_MCP](../../../../docs/REVIEWER_MCP.md) 调实际首轮／续接，保存真实返回和身份，不把 router 输出当执行。槽位不足可顺序取得两个独立意见；不要重派已有在途任务。评估者没有启动下一研究阶段的权限，全部结果回原调度者。

## 4. Root 必须消费为决定，并执行下一动作

对照原件处理两份判断。不是投票，不给完成率评分，也不把 reviewer 建议当定理。已有反例或直接证据可以裁定误读，保留分歧与依据。用现有 `ROUTE_REPORT`／证明记录写下瓶颈、原回复位置、采用的判断、撤下和保留的任务、实际下一动作及下次检查点；`NEXT_SESSION` 只留当前决定和链接，wiki 记录可复用条件、失败域与重试依据。

| 决定 | 调度者紧接着做什么 |
|---|---|
| 有界继续 | 给当前义务一批有具体成功/失败判据的工作，限定范围和资源；说清它怎样解除剩余不确定性，收回后立刻作决定。 |
| 补连接／换表示 | 先派缺失的真实选取、覆盖或共同约束；停止在旧松弛上继续加表。新表示要回到原题验证保真和实际收益。 |
| 转路线 | 交 route-loop 一个明确要绕开的障碍和最低区分性探针；保留未受影响的有效引理，不从零重做全部准备。 |
| 装配与核验 | 现有必要条件已够，停止更强搜索；交原 caller 装配并进行本题要求的 verify。局部完成仍回局部调用方。 |
| 收束当前分支 | 保存正确条件工具和失败范围，撤掉无下游用途的待派任务，转其它已授权义务。原题未解就明确未解，不判原命题为假。 |

不能以“值得继续”无限展期：**同一未变方法、同一证据下只允许一次重评后的有界探针续行。** 若仍未产生能改变原题完成路径的证据，不再原样续派；改实际表示/义务、接替代方向或封存此分支。改名、增模型、换参数碎片不构成改法。等价新规约若未改善关键未闭连接、后继联合域、可用求解工具或端到端成本，也不构成重置展期的新方法／新证据。若有真正新连接、可行完成计划或新资源证据，则说明它改变了什么后重新判断，不把一次失败变成永久禁用整个数学方向。

**保护必要完整计算。** 若原输入的无损归约与覆盖已经成立，检查谓词可靠，有限剩余域明确，实际吞吐、内存、存储和复核可承接，且完成会关闭一个真实必要义务，可一次批准完成这个有限计划，按实际范围回收。计划内分块无需每两批请两个 reviewer，也不要求途中再发现新定理。出现遗漏、成本失控或下游接口改变时才重评。代理自主推进的稳定编译/必要核验也按具体完成计划处理，不能借效率删掉覆盖或形式化要求。

全局决定由原 dispatcher 启动一次。局部 survey/verify 仍回原义务；proof-checker 和 route-loop 内部已有循环在其安全返回处提供结果，不同时改写同一正文、不用重评替换必要的修复和核验合同。成熟成果立即消费，重评本身不能变成拖延装配的理由。

## 5. 服务失败、恢复与准确报告

评估服务失败先查真实状态，保存失败，不自动重发付费调用。可用的独立 native 会话可以完成本次进展评估，注明实际身份；它不能替代用户另外指定的跨模型数学终审。只有一位或没有独立工具时，如实记录“独立重评不完整”。Root 仍可做保守有界诊断、回收成果、装配已足够结论或推进无依赖工作；**不能因服务不可用就自行解禁有争议的昂贵旧路线扩批**。同一家族两位可用评估者足以完成调度判断，不制造必须等外部模型的通用门槛。

局部预算用尽和分支停派不自动暂停整个 Goal，也不启动新 Goal。用户暂停、总预算与授权仍按宿主真实状态处理。恢复时先读上次决定、计数所对应的数学瓶颈和重试条件；不能重开旧会话后把无收益规约重新介绍为新进展。

报告区分“规约有效”“对完成路径有用”“本次实际执行了什么”。本协议是 Markdown 执行要求，依赖 agent 真正读取并执行，不是后台自动监测器；未测长程研究不能声称已消除局部陷阱或节省某比例 token。

## 6. 两种必须作出不同决定的实证

[既有两题转折](../../../../development/workflow-redesign/REAL_PROJECT_TRANSITIONS.md) 的 Property B 36 研究中，增加旧位置松弛的布局不能消去完整小点数义务。全局回看应转向真实平衡染色状态及唯一坏边交换，先交出覆盖整类的计数引理；后来的 ≤18 点结果也只关闭该分支，19–25 点仍需处理。它说明正确局部技术可以保留，但下一批应改变实际障碍，而非继续添加布局。

同份原件的 ECC 43/10 研究则相反：完整母码覆盖已接好，第二实现重扫全部陪集解决真实“无遗漏”义务，不能因规模大而跳过；随后所有兼容图无边，较弱必要门已排除三行扩张，此时应直接装配原题，停止更贵三行搜索。两种决定都从剩余原题义务出发，不从计算量大小或规约数量出发。这里只用历史证据说明操作，不恢复它们的研究、不冒称本协议曾用于产生历史成果。
