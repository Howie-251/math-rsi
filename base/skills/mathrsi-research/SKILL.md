# MathRSI 数学研究主工作流

给定数学问题，从准确读题与调查已有工作开始，推进到可检查的证明、构造或原题允许的反例；尚未解决时留下有用结果与精确恢复点。本入口负责**实际执行和衔接五个子工作流**。子工作流内部再调用数学技能、ARIS完整实现和领域方法，其真实输出成为下一项工作的输入。

```text
mathrsi-prepare
  specify初步 → survey（原文/反例/勘误/wiki）→ specify定稿
       ↓ 原规格、进口与已知边界
mathrsi-route-loop
  方法提案 → 对抗意见 → 推导/计算探针 → 修订 → 首批具体义务
       ↓ 可执行路线（允许尚未证明的数学义务）
mathrsi-prove
  formula-derivation / proof-writer / 领域方法 / 并行作者与核算
       ↓ 实际证明、证书或原题允许的反例
mathrsi-verify
  按需assemble → 独立核验 → proof-checker修复回路 → 按需Lean
       ↓ 原题范围内的结论与真实验证证据
mathrsi-handoff
  完整可读证明 → 复现与按需HTML/包 → wiki、恢复与交接

route-loop 或 prove ──具体新问题──→ survey ──原文结果──→ 原义务
verify ──实质数学缺口──→ prove ──路线失效──→ route-loop
prove ──局部提前验证──→ verify ──该义务结论──→ 原prove调用处
```

这是完整研究的默认路线。已有有效产物直接接用，短证明快速闭合；并行和回流由真实障碍决定，wiki贯穿全过程。在已授权范围内同一轮接着行动，不用阶段完成提示替代下一步执行。

## 进入：找回原题和真实断点

读任务约定、用户本轮指令、原题及 `NEXT_SESSION.md` 或现用入口。再读当前相关wiki实体、路线、证明与验证，确认已有产物可以接哪一步。导航负责定位，原证据支持事实；旧“运行中”状态核到实际进程或产物，已完成worker结果立即读取使用。

研究产物属于任务工作区，见 [WORKSPACE](../../../docs/WORKSPACE.md)。原题暂停时读材料或维护技能不恢复研究；用户已授权继续，就从断点行动。Goal、暂停和预算以用户及宿主真实状态为准，不自行创建Goal。

| 当前材料与请求 | 首先执行 | 读完产物后接什么 |
|---|---|---|
| 新题或定义未明确 | prepare | 原规格与调查接路线设计 |
| 规格/调查完整，尚无可执行方法 | route-loop | 首批具体任务交prove |
| 在途证明、有效路线和可信断点 | prove | 使用已有成果闭合当前义务 |
| 完整候选、见证或反例 | verify | 核原题证据，修实际缺口 |
| 只缺阅读页、包或暂停交接 | handoff | 按真实状态交付 |

独立调用子工作流尊重其范围。授权解题到底时，子阶段返回边界后由本入口接棒。可短证的问题直接写完整推导与相称核验，不制造多条路线、探针程序或空目录。

## 怎样实际调用和消费

调用意味着先读对应完整SKILL，执行相关流程，再读它返回或写出的内容。主agent可在同一上下文执行，也可给worker完整任务。它不是必须存在的Shell命令；宿主支持发现时用原生技能名，否则明确读取本仓路径。

| 子工作流 | 内部实际能力 | 主流程要消费 |
|---|---|---|
| [mathrsi-prepare](../mathrsi-prepare/SKILL.md) | [specify](../mathrsi-specify/SKILL.md) → [survey](../mathrsi-survey/SKILL.md) → specify | 原规格、原文进口、调查范围、当前状态 |
| [mathrsi-route-loop](../mathrsi-route-loop/SKILL.md) | 方案推导、适配ARIS审阅机制、必要探针、修订 | ROUTE_REPORT与首批具体数学任务 |
| [mathrsi-prove](../mathrsi-prove/SKILL.md) | ARIS推导/证明、领域方法、并行作者、按需跨轮证明管理 | 真实局部结果与原题连接、候选或准确缺口 |
| [mathrsi-verify](../mathrsi-verify/SKILL.md) | [assemble](../mathrsi-assemble/SKILL.md)、独核、proof-checker、按需Lean | 正文、真实audit、计算/形式证据和scope |
| [mathrsi-handoff](../mathrsi-handoff/SKILL.md) | 阅读交付、引用、复现、ARIS渲染和wiki | 可读解答、复现入口、HANDOFF和恢复页 |

默认文件名由子技能说明，已有任务沿用原名。一次调用传清任务目录、原规格、当前输入、具体义务、允许假设、输出归属和适用预算。复杂步骤按子技能执行，不把所有技能全文塞进每个worker。

**同级阶段只由一个调度者启动。** 本入口的执行者是当前研究的阶段调度者；调用任一子工作流时，明确“完成指定scope后返回产物和下一动作，不自行启动同级下一阶段”。Root收到后读取并启动下一步一次，worker不能先启动它、Root又重复启动。子流程内部真正需要的动作照常执行，例如prepare调用specify/survey、route-loop调用探针或survey、prove提前调用局部verify、verify调用assemble/checker/Lean；每个内层调用都返回直接调用方。发生跨阶段数学回流时，由持有该义务的调用者决定并执行一次，不让多层同时接管同一队列。

用户独立调用某个子技能，默认只做那一范围；若明确授权持续完成研究且没有上层调用者，该执行者可读取本主入口接任调度，从当前结果的后继继续一次。以下调用块均继承上述返回约定，不需要新JSON字段或调度脚本。

ARIS双端实现及helper见 [ARIS_REUSE](../../../docs/ARIS_REUSE.md)。Codex读 `base/skills/skills-codex/`，Claude读 `base/skills/`；MathRSI新技能为宿主无关Markdown。命令显式指向本克隆 `base/tools`，不依赖作者其它ARIS目录。只采用当前真实技能支持的参数。

## 1. 准备问题，得到可用规格和文献

每个子阶段返回时给一段可直接接棒的短答复，例如：“产物`work/L/PROOF.md`，范围为所有满足A的输入；已证明L；原题还缺`PROOF_DRAFT.md`§3中`H⇒A`；建议回prove补该连接。”主调度先读这段，再读决定下一步的原产物，不从头重读未变的全部历史。阶段作者用现有报告返回即可，不必另建一份回执文件。

调用prepare，交用户原话、题面、现有wiki和插件。它用specify形成可搜索表述，用survey完成广搜、原文核读和wiki，再用specify消费调查定稿。新题查异名、引用链、反例和勘误；已有调查只补当前差异。

```text
读取 mathrsi-prepare/SKILL.md 并执行。
工作区 <W>，原问题及材料 <真实入口>，领域插件 <若有>。
先恢复已有规格、文献和wiki；新题完成首轮广搜。
返回原目标、已核进口、未确认来源与实际下一步；交回本流程继续。
```

收到后读原量词和允许终点，再读拟用定理条件及原文定位。找到现成解答可核对、复述或按用户要求另证，不再假装需要原创搜索。文献不足不能说无人做过；缺关键进口时补它，独立工作可以继续。

规格足够开展研究即进入下一阶段。目标解释有实质歧义才向用户澄清，调查在后续仍可回流。

## 2. 打磨求解路线，然后立即执行

调用route-loop，交规格、调查、已有工具和失败记录。它比较真正能推出同一义务的替代路线，区别必须合起来覆盖原域的分支；针对未知成本实际推导或试探，围绕具体数学疑问进行有界跨模型讨论，保存原回应并据证据修订。

```text
读取 mathrsi-route-loop/SKILL.md 并执行。
原题 <spec>，可用进口/成果 <文件>，当前阻塞 <若为恢复>。
检查任意原输入怎样进入中间引理，以及结论是否推动目标。
必要探针实际推导或运行；按已授权reviewer做具体对抗讨论。
交 ROUTE_REPORT.md：选定路线、未证义务、证据及首批可执行任务。
这是路线迭代，分数或模型同意不表示定理成立。
```

Root读报告，判断下一行动怎样改变原缺口。可行动路线可以含未证引理；应明确假设、输入连接、下游用途和先做什么。把第一批任务直接交prove，不能在这里只交计划就结束已授权解题。

这层执行 ARIS auto-review-loop 的数学适配，由 route-loop 持有外层轮次：恢复、审阅及证据对话、实质修正、结果回收、带新证据复核、逐轮记忆与终轮交接都要实际完成。research-review通过显式composed接口把当前审阅产物交回同一累计报告；它的对话不另起一个修法调度者。原版训练/投稿评分门改为本次数学路线的交接判断，最终证明仍由proof-checker验收。跨模型通过仓内[Python MCP桥接](../../../docs/REVIEWER_MCP.md)和宿主工具执行；router只解析配置，实际调用与回复必须存在。子循环额度用完返回最有根据的下一动作或精确缺口；Root继续其它授权工作，不因此自动暂停Goal。

## 3. 推进证明，立即收回可用成果

调用prove执行选定任务。它实际用formula-derivation稳定对象与推导，用proof-writer写准确引理，用领域方法做结构/计算，将可独立验收工作交worker。Root保留原量词、共同对象、关键决策与最终验收；完整产物一到就核查并接下游，不等全批齐备。

```text
读取 mathrsi-prove/SKILL.md，执行 ROUTE_REPORT.md 的首批义务。
原题 <spec>，当前最关键连接 <任意原输入怎样满足L条件>。
复用 <证明/源码/wiki>，实际写证明或执行必要计算。
按模块/义务独占写入，交付真实caller并立即回收使用。
局部问题直接修；路线假设被击穿或连续无信息则交回route-loop。
```

每次收到结果，读它实际证明的命题及条件。全称结论核原输入连接；存在性核见证；计算排除分别核目录覆盖与拒绝判定。条件定理保留长期价值，但它的上游条件可不可得单独记录。细节见 [proof-evidence](references/proof-evidence.md) 与 [efficiency](references/efficiency.md)。

高风险子引理可以提前调用局部verify；核验完成回同一prove调用处，不进入最终handoff。Lean也可提前处理真实接口风险：数学缺口回prove，库/API问题留在形式化内。成熟的较弱必要判据若已经足够结束原题，立即装配，不再展开更强的计算。

完整候选马上交verify接全链，不默认再提高参数或多生成样例。仍开就处理准确义务，不把局部表数量换成完成百分比。两轮没有信息增量时Root检查共同约束、表示、引理是否过强和实际成本；有依据仍可继续原法，不机械换线。

## 回流文献：带问题返回，再带事实接回

route-loop和prove均可直接调survey增量路径。候选选点引理被击穿，交当前对象域、失败实例、需要的替代条件和查过的来源；文献进口疑似不适用，交实际版本、调用处与缺失假设。survey补查原文后将结论送回原义务，而非重新启动整套prepare。

Root必须消费新信息：新定理适用就证明输入条件并接入；只有弱化版本则留作条件工具并继续原目标；路线被否定就重选受影响部分。已证独立引理与未变调查继续用。只有原题解释受影响才回specify。

插件提供领域术语、旧失败域与引用定位。返回“此工具不适用”也是有效信息，应改变下一行动，不是重复调用到得到肯定。

## 4. 装配与验收，消费真实证据

调用verify，传原规格、实际候选和证据。分散片段由它调用assemble；完整稿直接核原输入、覆盖和实际算术，再执行proof-checker。纯解析稿不制造证书程序，计算稿不以程序成功省掉覆盖，按需Lean不更换原目标。

```text
读取 mathrsi-verify/SKILL.md，执行完整原题范围。
原题 <spec>；候选 <入口>；证据和允许进口 <文件>。
已有完整稿直接用，片段按assemble接通。
按本宿主proof-checker实际合同审计与修复，Markdown按其输入适配。
Lean范围 <用户要求/具体义务/不需要>；返回真实VERIFICATION及audit位置。
```

Root读真实audit未闭项、独核范围和形式声明。文字遗漏或索引错误在验证内修并检查受影响处；需要新数学/选取/分类则带caller交回prove。proof-checker拥有证明修复回路，主流程不另套“直到所有模型赞同”。原回应保留；模型误读可据数学事实反驳，不能篡改成对方PASS。

原目标成立且本任务规定的核验齐备后进入handoff。指定服务失败时分别保存已成立数学与未完成审阅，继续独立工作；等待不是认可，服务失败也不是数学反例。局部scope始终返回原调用方。

## 5. 交付完整解答，保留可恢复研究

调用handoff，给正文、VERIFICATION和用户实际交付要求。它完成相应引用、阅读视图、复现或打包，更新原wiki与NEXT_SESSION。需要HTML时核心证明写入可读正文，源码给深读入口，不能只放MD链接。

```text
读取 mathrsi-handoff/SKILL.md 并执行。
原题 <spec>，正文 <proof>，真实验证 <verification>。
交付要求 <实际需要的Markdown/PDF/HTML/包>。
复用有效数学证据，按需要独立目录复现，保持准确scope与进口。
更新原wiki和恢复页，交原结论及剩余事项，不扩研究参数。
```

用户要求暂停就交严格部分、失败条件与下一动作，不为交接继续解题。渲染/链接故障在交付内修；新数学或证据缺口才回verify/prove。交接完成不冒充数学完成，数学成立也不替代明确要求的复现材料。

## 领域插入与已解题经验

[PLUGIN_CONTRACT](../../../docs/PLUGIN_CONTRACT.md)规定插件接收当前义务并返回数学产物。Property B的实际入口是survey中的 [propertyb-literature](../../../plugins/propertyb/skills/propertyb-literature/SKILL.md)，route/prove中的 [propertyb-bound-lab](../../../plugins/propertyb/skills/propertyb-bound-lab/SKILL.md)，verify中的 [propertyb-certificate](../../../plugins/propertyb/skills/propertyb-certificate/SKILL.md)。交清阶段与scope，只执行相关部分，避免领域技能再递归启动整个通用流程。

这套衔接以两个已解项目的实际工作为依据，详见 [实证转折](../../../development/workflow-redesign/REAL_PROJECT_TRANSITIONS.md)。Property B T33中，24点局部分支接成实际caller后，返回仍开放的23点继续，最终由全部点数分支装配新Main得到原染色。局部核验不是最终交付入口。一般k研究从RS原文重新对齐组合基线，再把同一实际超图的结构与概率估计接起来；文献回流给出了可用接口，不只是论文目录。

ECC旧43/10题中，文献类别上限与实际代表合法性、互异性共同闭合目录；完整遍历与低权拒绝见证承担不同义务。较弱配对必要条件全被排除后即可结束原题，无需继续更昂贵的三行扩张。发现代表可以启发式，覆盖则需要严格证据。新45/11、五元35的Lean及36研究仍未完成，不能因方法可复用写成它们已解。

新经验先进入任务wiki，记准确条件与来源。值得跨题复用的按[独立维护工作流](../../../docs/EVOLUTION_WORKFLOW.md)提炼：由维护owner读真实证据、修改实际调用、组织针对性审阅及独立使用试验，再消费结果决定修订、拒绝或纳入下一版。这个流程只在相应维护授权下执行，不是每次解题后自动触发；解题中不改base、不降低原验收。archive是复用资产，旧Goal不是当前授权，按当前义务读原材料而不从零重做已有研究。

## 一轮执行结束时

报告原目标真实进展、已闭具体义务、剩余障碍和已经执行的下一步。长任务更新原恢复页、wiki和真实在途工作；短任务直接交解答。不用模型分数、文件数量或代理退出状态代替数学成果。

满足原目标及本任务交付才报告完成。有有效未闭工作且授权继续，就执行相应后继或回流，不把一份计划当成解题终点。
