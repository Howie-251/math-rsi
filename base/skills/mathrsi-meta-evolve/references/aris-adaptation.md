# ARIS meta 能力在 MathRSI 中怎样实际执行

这份参考固定 mathrsi-meta-evolve 的复用与差异，避免“复制了目录”被当作已经完成编排。入口是 [主技能](../SKILL.md)，基线来自仓内完整原件：

- Claude：[meta-optimize](../../meta-optimize/SKILL.md)、[meta-apply](../../meta-apply/SKILL.md)；
- Codex：[meta-optimize](../../skills-codex/meta-optimize/SKILL.md)、[meta-apply](../../skills-codex/meta-apply/SKILL.md)。

源版本和文件由 base/ARIS_SNAPSHOT.json 记录，版权在 base/LICENSE。MathRSI 的适配不覆盖这四份文件。运行时 helper 指向当前克隆 base/tools，不能回退作者机器的 aris_main。

## 从上游流程保留的实作

meta-optimize 的 Step 1/1.5 要从使用、失败、人工修正和上轮结果找当前瓶颈。数学执行时，协调者读原目标、实际操作与转折，写出哪项义务／调用现在制约工作；下一轮先判断旧瓶颈是否解决。可以有独立的多个真实问题，不为“一句话瓶颈”删掉它们。

Step 2/3 将机会变成最小真实 diff。数学执行时先读现有 SKILL 及实际上下游，若 v1 已有正确机制就复用；若缺某个判断、返回或输入绑定，就在那个位置改。必要的跨文件契约作为同一逻辑修改处理，不机械每文件一个提案。删除重复检查、无用包装也是合法改进，但要保留真实验收。

Step 4 的对抗审阅保留原件、实际模型身份、完整回复与修法。MathRSI 实际调用仓内 research-review 的 composed 维护接口，完整过程在主技能第4节；模型意见是需要解释和处理的证据，不是不可反驳的真理裁判。

meta-apply 强调判断实际待落地 diff，不能信作者自写 PASS。MathRSI 的协调者同样读取实际文件、原始意见和使用结果再采用；使用者可以是 Root 本人，具体核对可委派。没有真实独立运行就不标“独立通过”，也不为每次维护强制另造无历史完整测试。

版本与过程记录保留，用现有 Git 和维护报告即可。没有实际提交就记录工作树状态。来源或审阅收据不是内容正确性证明，不再叠加新的散列体系。

## 数学适配必须显式替换的部分

| 原版机制 | 本技能怎样执行 |
|---|---|
| 必须有 events.jsonl，至少五次调用 | 接受真实研究档案和原件定位。一个可复现接口错误足以修复；无事件日志不伪造日志。频率或提速主张仍需实际数据。 |
| 投稿评分／轮次收敛 | 观察原义务、证据与真实调用有没有推进，不用分数判定理真值。 |
| 只改 harness | 先判断 base、领域插件、单题、暂缓；不把领域定理或一次 UNKNOWN 写成通用提示。 |
| Codex optimize 的 Step6 自行 apply，与 applier 的只读 producer 描述不一致 | 由本技能唯一协调者管理候选作者、讨论、使用与采用；不混称执行了互相矛盾的原协议。 |
| 上游 meta-apply 明确的单独人工调用门 | 本技能按用户已有维护授权工作。若用户选择原样 meta-apply，遵循它自身合同；不能冒充它已经运行。 |
| 模型 PASS/KILL 决定是否可采用 | Root 核真实缺陷、改法和反驳。失败或截断不算认可，模型误读也不成为永久禁止。 |
| 先落地，提醒下次测试 | 本次修改后即实际使用受影响部分；无需全题重跑，也不强制由无历史代理执行。 |
| 用每个新模型名字触发“减负” | 名字变化只提示重新看能力，删除步骤仍须具体证据。 |
| 自动 hooks 与全局采集 | 本技能不自动安装；现有日志可读，缺日志不阻塞原件取证。 |

这些替换来自数学维护的真实需要与当前用户要求，不改 ARIS 原版契约。记录运行名称为 MathRSI 数学 meta 适配，不把原版工具的字段填成虚假 PASS。

## Helper 和 MCP 的具体边界

现有 capture_filter.py 可在提案有环境失败或模型能力判断时辅助检查，使用前读它的实际 CLI。一次网络 EOF 不支持“永不使用此模型”；永久保留一个数学反例则是正确知识，不能被通用负面描述过滤器删掉。

reviewer_route.py 解析配置，不执行 reviewer；实际调用走宿主 MCP 与本仓桥接，见 [REVIEWER_MCP](../../../../docs/REVIEWER_MCP.md)。保存返回身份、会话及读取／执行范围，指定 reviewer 不可用时保留缺项并推进独立实现。

meta_opt/trigger_eval.py 是 Claude Code 的选择探针，不能冒作 Codex 实测；它测“是否选到技能”，不测数学能力。没有触发错误的具体问题，就不为了维护运行一次付费选择评测。

meta_logging 模板的默认位置和 corpus_write_guard 的路径匹配不是 MathRSI 全路径隔离保证。当前合作开发直接按明确写域、实际 diff 与用户权限工作，不安装无必要的防御平台。

## 一次完整的消费关系

研究档案产生可核事件，例如“新增边后沿用旧图的坏点对拒绝候选”。取证者交原对象、修改关系、旧证书和新失败；协调者读现行 prove/verify，决定缺少的是重新判断证据适用范围的动作。作者把该动作补到实际步骤，DD 插件同时提供保距引理与失败失效实例。模型讨论针对适用方向，Root 修真正错误。随后 Root 用同一实际场景按修改后步骤决定保留／重算哪些证据，并记录实际决定与命令范围。

最终消费的是行为和产物，不是“提炼成功”的标签。某旧证明仍有效就明确继承；某负记录依赖被修改的边集就不能照搬；没有必要重算的完整旧图则直接复用。这就是从证据到已有版本改动的一轮，而非新起一个主干。
