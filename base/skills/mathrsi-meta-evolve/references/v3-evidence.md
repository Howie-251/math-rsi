# v3：在实际caller消费候选、运输和有限证据

本页支持route-loop、prove、verify和handoff的增量动作。它是维护实例；恢复这些历史材料不授权启动旧研究。原包随领域插件保存，当前研究产物仍写本次任务自己的工作区。已有共同对象、完整覆盖和证据继承规则继续使用，本页集中说明新增的实际接缝。

## 1. 工作集候选、全域反馈与接受最佳

Erdős 86的工作集优化记录在[deep_history](../../../../plugins/hypercube-extremal/archive/source/research/Q4_refined_research_20261027/deep_history.json)：run0全域upper为0.8347202840891347，保留best为0.5934560950743827，并added=800。池内改善不能消费成同一阈值的全域界；领域返回的违反对象/行才是下一轮补约束的输入。该历史JSON只记录补行数量，不能从它重建那800个对象；若接续此轮，需按领域的源程序/数据取回对应行或重做已授权的分离，不能由数值猜见证。这个候选失败不否定共同旗方法。

另一个[full_flags_history](../../../../plugins/hypercube-extremal/archive/source/research/Q4_059970530_research/full_flags_history.json)有180行：探索全域最好是iteration178的0.5997052622754959，末行179为0.5998952182400273。caller应取178的候选快照继续认证，不能从末行导出相同界。历史浮点best本身也不是已严格接受best；认证后只能引用认证所绑定的精确文件。

最终强证书的[整数因子](../../../../plugins/hypercube-extremal/archive/source/certificate_final_q4/certificate_control.json)与[精确结果](../../../../plugins/hypercube-extremal/archive/source/certificate_final_q4/result_control.json)给出23662061277957791/40000000000000000，外向小数0.59155154。文件中的q5命名不能决定模型身份；实际q5_cuts为空。PSD来自实际整数因子构成的Gram；有限逐图界还须在完整域重计，渐近结论另用原平均引理。修改因子、舍入、删块均改变分数，旧最坏图只是诊断输入。领域checker与证明桥负责这些数学事实，base负责让候选到最终对象的证据不串用。

一次可执行的调用是：“给定候选C、当前工作集W、最终域D和已接受证书B，返回C在W和D的值/未核范围；若D上违反当前阈值，给重建违反对象的文件与标号；若改善，保存C快照交精确化。不要覆写B。” 收回后原prove消费：违反对象补W；全域浮点最佳进入精确化；精确对象在D上认证并接原题后才替B。恢复时从未完成的分离/认证接续，保留最后迭代与已接受版本各自状态。

## 2. 带标记的归约需要实际运输

Q6的[SOURCE_AUDIT](../../../../plugins/hypercube-hamilton/archive/source/research/six_directions/SOURCE_AUDIT.md)指出：“全图极大且避根”比“删根图上极大”更强。Q2中M={23}在删0图上极大，不能在保持0自由时再增广，但它在全图还可加01。专门生成前者会漏原输入；这不是Hamilton路径反例。无根轨道也不能替每个自由根的带根轨道。

调用归约时给同一份(M,u,v,必含边,其它标记)，要求每个变换返回实际同构/增广、标记的像、逆向恢复。复合后由caller代入原M核结论，不只比较每层代表个数。Erdős同步根群的相对朝向属于同一接缝：共同作用保留两臂关系，独立取商只是更弱模型。领域资料负责给真正的作用和稳定子，不把某个根群写成全领域规则。

[TWELVE_STAR_MAXIMAL_A_REDUCTION](../../../../plugins/hypercube-hamilton/archive/source/research/six_directions/TWELVE_STAR_MAXIMAL_A_REDUCTION.md)提供更细的原伙伴/补全伙伴区别。原内部匹配L增广到L*，原目标伙伴为h，补全中可能另有h*。证明明确L'⊆L*'，并用D=D*∪(L*'−L')把新增边归为最终删除的辅助边；若目标原来跨面，不能因补全后内部匹配就改用h*恢复原边。实际caller需保存原h和这些集合，删除辅助边并恢复原v—h，才得到原M的路径。该文件保留当时“有限义务开放”的历史状态；后来完成范围查插件当前总装，不能用此旧文覆盖后续验收。

若某次运输只保留局部匹配、不保根或目标，返回准确失效标记，修归约或重新做带标记覆盖；其它有效局部证书继续保留。这里新增的是可交回、可复合、能恢复的实际映射，不能用一句“共同对象”代替它。

## 3. 有限证书怎样承担全称义务

[A10_ORBIT3_UNIVERSAL_PROOF](../../../../plugins/hypercube-hamilton/archive/source/research/six_directions/A10_ORBIT3_UNIVERSAL_PROOF.md)将22端点完全图匹配域的21!!=13,749,310,575个输入转为1024个合法短森林与1024个匹配列。用的是明确进口rank_GF(2)(H22)≤1024；有限子矩阵满秩说明选定行张成整个行空间；每个原匹配对应列都非零，所以至少一选定森林与它连通。展开森林路径后得所需圈并保留任意必含匹配边。这些箭头才是有限证书覆盖全称域的原因，1024这个数本身不能证明覆盖。

[独立checker记录](../../../../plugins/hypercube-hamilton/archive/source/research/six_directions/A10_ORBIT3_UNIVERSAL_REVIEW_check.json)实际核1024森林、1024合法列、1,048,576个连通位及rank1024，明确未检查全谱发现过程穷尽；该穷尽不是这个证明的前提。读历史记录是证据消费，不是本轮重跑。新任务调用应同时交精确端点域、森林展开条件、进口量词、有限checker与实际caller；只给“rank1024 PASS”缺少原结论桥。

[TWELVE_STAR_MAXIMAL_A_FINITE_PROOF](../../../../plugins/hypercube-hamilton/archive/source/research/six_directions/TWELVE_STAR_MAXIMAL_A_FINITE_PROOF.md)采用另一接口：旧森林池缺秩，仍可从中为每个实际局部极大匹配选择合法正证书。现在要证的是新输入域完整且每个输入有合格证书，再经增广单调还原回原M；无需旧池穷尽或满秩。缺秩只否定该充分论证，不给原题反例。正证书合法性仍逐项核，不能因“失败资产复用”跳过。

base遇到大域时向领域询问的是这样的机制及其条件；有限基、覆盖或解析论证都可以。若没有适用机制，保留真实成本与未闭义务，按授权选择继续计算或换路线，不机械要求所有问题求秩。

## 4. 混合Lean的参数边界

ECC42的[Main.lean](../../../../plugins/ecc/archive/source/formal/ecc42/ECC42/Main.lean)中，`reduction_42_16_to_41_14`核内证明从CodeExists 42 16 13到ExactCodeExists 41 14 14；`nonexistence_of_proposition2 (hProp2 : Proposition2)`接受文献命题为显式参数。`nonexistence_explicit`将它展开为无相应41位14维、精确距离14子空间，并对实际42位子空间、维数和重量假设推出False。

即使传递公理仅标准三项，hProp2仍是定理参数，不会被公理列表列成未证axiom。verify需读类型/定义，将hProp2接到准确文献进口，并分别记录核内归约、外部定理与实际下界矩阵。矩阵是否真的接入出口要读它的实际常量/合法性证明及最终调用；数据文件[lower-generators](../../../../plugins/ecc/archive/source/data/lower-generators.json)存在不等于形式声明已使用它。若目标本来只要条件归约，就按该目标验收；若目标要原最优值，还需外部上界依据与合法下界见证。

handoff随声明交这份参数边界和真实checker入口，既复用Lean已证的归约，也使下一个研究者知道尚可继续核内化的是哪层。本轮维护不重跑Lean、不把外部计算改写成核内证明。
