# 数学求解路线迭代

本工作流负责**提出方法、质疑方法、实际试出关键信息，再决定怎样求解**。它位于准备与证明推进之间，也可以被证明推进中的具体表示障碍回调。交付不是一组愿望或若干模型的赞同，而是一条足以立即展开的路线、支持其选择的实际材料、仍需证明的条件，以及首批可以执行的任务。调用后执行到这个交接点；不要只给用户列一个计划便停止。

这是一项独立的研究方法循环，借鉴 ARIS review→fix→new evidence→targeted re-review 的动作顺序，实际组合 MathRSI 领域技能与仓内 ARIS 的原件读取、reviewer路由、trace及推导/证明能力。**轮次和终点由本技能拥有**，不嵌套执行原版 `auto-review-loop`，也不嵌套 `research-review` 直到论文共识的完整循环。它不等同于最终 `proof-checker`，不把 score、ready/almost 或模型同意当定理真值。路线值得推进与原命题已经证明分别报告。

**阶段调度归调用者。** 被主工作流或其它caller调用时，完成本次路线范围后，只返回产物、准确剩余和建议next，不自行启动同级prove或其它下一阶段；父调用者消费后负责启动一次。本范围内部的survey、proof-writer、领域探针和审阅照常实际执行，嵌套结果回到本次路线义务。用户单独调用本技能时只做所请求范围；若用户明确授权持续完成全研究，本执行者在本阶段结束后接过主调度，读取mathrsi-research，从后继继续一次，不让父子各启动一遍。

## 输入、写入与实际技能位置

先读本次任务的正式规格、文献交接、当前恢复入口及相关失败。默认名称为 `FORMAL_SPEC.md`、`LITERATURE.md`、`NEXT_SESSION.md` 和已有路线报告；用户或上游已指定其它文件名时沿用。文献交接可以是现有来源地图和 wiki 链接，不要求为了本技能复制出一份同内容的 `LITERATURE.md`。

从这些输入确定原对象、量词、参数、允许的进口、允许的解答与预算；从插件读**当前方法需要的**数学与失败知识。没有插件的领域照样可以研究，用已有文献和实际论证补足；不要把某一领域的锁点、母码或有限枚举做成通用前置。原目标未明确或关键进口缺失时，交给准备阶段补确切问题，其余不依赖它的推导仍可进行。仅阅读技能或历史案例不恢复暂停的任务。

默认由本轮协调者唯一写 `ROUTE_REPORT.md`；若上游指定已有正文中的一个路线节，就直接维护该节。报告放在**任务工作区**，不写回 MathRSI 或插件知识库。任务作者只写各自行动子目录，返回新增内容和证据路径；不得同时编辑共享报告、正式规格或已有总账。不要求 JSON 状态机或固定数量文件。

实际执行前完整阅读本仓对应宿主的入口：Codex 用 `../skills-codex/<name>/SKILL.md`，Claude 用 `../<name>/SKILL.md`。只按当前动作读取其资源。调用与本副本 helper 的绑定见 [ARIS_REUSE](../../../docs/ARIS_REUSE.md)，显式使用当前克隆的 `base/tools`，不回退作者机器的全局 ARIS。与本技能衔接的入口是：

- [research-review](../skills-codex/research-review/SKILL.md)：读取其原始工件取证、first/reply和trace方法，适配为本循环拥有的单个数学路线审阅slot；同一具体争议可沿原session续接，不启动其完整共识循环。
- [formula-derivation](../skills-codex/formula-derivation/SKILL.md)：当核心量、松弛和恒等式尚未理顺时形成推导包。
- [proof-writer](../skills-codex/proof-writer/SKILL.md)：当路线依赖已经明确的关键引理时，直接尝试证明或反驳它。
- [research-lit](../skills-codex/research-lit/SKILL.md)：新障碍暴露新术语、等价问题或遗漏进口时定向补搜；接回已有文献交接，不重启整份调查。
- [mathrsi-survey](../mathrsi-survey/SKILL.md)：向准备阶段回传一个准确的新文献问题，消费原文条件和来源后回到本轮原义务。
- [mathrsi-prove](../mathrsi-prove/SKILL.md)：本阶段的交接对象，由调用者消费所选路线后调度；不是进入路线循环就要执行的子技能。

## 1. 恢复真实断点，选本轮需要改变的决定

已有报告时，先看最后一次决定、未证条件、审阅原始回复与探针结果，再查在途worker、外部审阅或程序是否已真实完成。可消费的产物立即回收；不因报告写着“运行中”就另启同一任务。已证明的条件引理、已排除的固定域与有效进口保留，不从零提出一批相同路线。

在报告中自然写清本轮的决策问题。例如：“现有上界未严格，究竟是常数算错、活跃项未改，还是把同一对象的不同投影独立放松所致？”随后选择本轮能改变该判断的一次推导或探针。不能只写“提高界”“再问专家”或“扩更多表”。

按当前任务余量给这次探索一个实际边界：它可以是一次短推导、一个小而真实的完整子域、一份关键论文证明，或一段明确的CPU/内存预算。未指定轮次时，本次子调用默认最多3个实质路线轮次，可被用户预算或任务需要调整；一轮包括提案、实际探针和对新增证据的处理，不把每次reviewer回复另算研究成果。先做最便宜有区分力动作，收回后再决定是否扩大，不自行承诺一夜计算。预算用尽返回可执行下一动作或准确缺证据，**不自动暂停整个Goal**。小引理可直接证完，随产物返回其下游用途，无须制造多轮竞赛。

## 2. 提出足以检查的候选方法

通常先写一条最有希望的主路线；只有确有不同机制、能够闭合同一义务的方案时再列替代路线。不同参数分支若必须合起来覆盖原域，它们是共同任务而非任选其一的替代路线。不要默认八路枚举或为凑候选数重复变体。

每条保留路线应讲清：从任意原输入或假定反例怎样到达工作对象，使用哪个已有定理或领域引理，新的关键命题是什么，假定它成立后怎样推出当前目标，以及最脆弱的一项条件在哪里。将已证、文献进口、待证候选分别标明；没有证明的“存在好选点”“可以同时规范化”“这些局部最坏情况相容”都保留为条件。

给出一个**提前连接**：不要求此时证明整条路线，但要把上游实际输入和下游所需结论写在同一段推导中。若新引理即使成立也不能改善真正活跃的界，先看它与其它改进能否联合起效；若毫无下游用途就改提案。条件引理本身有价值时保留它的准确用途，不把它伪装成原题进展。

报告写下拟执行的最低工作及不同结果将触发的动作，例如：“若两个松弛对所有参数恒等则停扩此DP；若只在某段相等则把剩余域交给更细模型；若发现实现错误则修正原实现，重新核受影响输入。”这使审阅者有具体对象可以质疑，执行者也知道什么时候应换行动。

## 3. 复用 ARIS 的审阅机制，执行一个数学路线 slot

读取相应宿主的 `research-review` 及 [reviewer-backends](../skills-codex/shared-references/reviewer-backends.md)、[review-tracing](../skills-codex/shared-references/review-tracing.md)，复用工件读取、路由、first/reply和原文留存。该slot只审本轮明确的数学问题，结束后返回本技能实作，不执行原技能直到投稿共识的所有阶段。遵循本次用户、项目及准备交接的实际reviewer要求。指定Grok或Gemini时沿真实路由调用；要求两者时分别完成指定问题，不以一个替另一个。没有指定时按当前路由规则，不凭桥接名字猜模型家族。

将原题、候选方法、关键进口、失败原件与具体问题的路径给reviewer，并要求它自己读文件；保留ARIS的review-scope-limits，避免要求无收益的防御和包装。将slot上下文适配为数学路线：关心可调用性、量词、必要条件、潜在反例、最便宜区分性动作与端到端成本，而非NeurIPS评分或额外GPU实验。说明这不是完整证明验收；若reviewer发现真实数学错误照常处理，不用“仅路线审阅”排除它。模型意见没有数学真理否决权：可以用原始证据反驳其错误判断，保留其原文及处理理由，不伪改成reviewer PASS。

可直接使用的调用任务如下；将路径换成本次实际绝对路径，并通过宿主真实暴露的工具执行，文字中的技能名本身不证明已调用：

```text
读取本仓 Codex research-review/SKILL.md及reviewer-backends/review-tracing，
复用其取证与路由，为mathrsi-route-loop执行一个数学路线审阅slot，
不启动原research-review的共识循环。
原题：/task/FORMAL_SPEC.md；文献：/task/LITERATURE.md；
候选及待证条件：/task/ROUTE_REPORT.md；失败原件：/task/work/old-bound/。
问题：两个局部上界是否丢失同一对象的共同约束？新联合量即使成立，
能否改善实际活跃项？请指出具体无效推论或反例，并给最低区分性推导。
这不是主定理验收，不要给论文分数；正确的部分直接认可。
选择路由：grok。把结论与实际trace路径返回route-loop唯一报告作者。
```

通过当前宿主实际暴露的selected backend发起调用；例如Grok首轮包含prompt、覆盖输入的cwd及已解析model/effort，reply只带threadId和prompt；Antigravity同样固定首轮cwd/model/effort。参数名与成功条件以所读backend契约及当前工具schema为准。slot将新增结论与trace位置返回协调者合入报告，worker不写共享报告，也不声称执行了未运行的ARIS完整循环。保留完整prompt、原始回复、实际模型/effort、session、完成状态、读取范围及是否执行程序；不自动重试一次失败的付费调用。

收到回复后逐条采纳、带证据驳回或缩小关切；reviewer提出新假设时先问原输入能否满足它，不能借审阅悄悄改变正式规格。同家族意见如实provisional；跨家族有效审阅也只是其范围内的路线判断。若指定审阅不可用，保存真实失败，推进不依赖该意见的推导和探针；本轮所需审阅未完成就不宣称“已审通过”。

## 4. 立即执行最低区分性推导或计算

根据本轮关切执行实质动作，不停在“建议验证”。对象或公式链不稳时调用formula-derivation，把目标、原对象、允许条件、当前不等式和输出路径给它；已形成准确引理时调用proof-writer尝试证明或找反例；领域结构问题调用插件的实际子技能。通过独占目录委派可独立验收的任务，主代理同时处理共同对象、关键数学和整体判断。

例如，向formula-derivation指定 `/task/work/route-joint/DERIVATION.md`，要求从同一个原对象推导联合表达式并分开标明恒等式、候选命题与松弛；不要仅让它把旧式子重新排版。向proof-writer指定准确关键引理与原题caller，收回完整证明、严格反例或缺少哪条条件；它若写出更弱定理，保留该定理并将原缺口继续列出。

计算探针使用真实输入或可明确解释的必要模型，并说明样本为何能区分本轮路线。先复用已有程序；需写新程序时固定它真正检查的谓词、参数与精确/近似算术。一个严格反例可以否定候选全称引理；必要模型中的坏型只能说明该模型太宽或该充分界失败，不能当原题反例。小域全过可估计成本、发现结构，不能据此外推全域。

不要将探索器本身必须穷尽作为路线门。若启发式得到一份目录，可以另以“所有代表合法且互不等价＋适用的已证分类上限”建立无遗漏；若直接得到目标见证，完整核验见证即可。反过来，逐一确认目录成员合法不会自动补上分类上限、误删或覆盖义务。先问最终结论需要哪一环完备，再选择最便宜的充分证据。

收回完整产物后立即读论证、关键输入与原始结果；对决定路线的算术或见证做相称复算，检查它影响哪一个判断。只复算影响该决定的内容，不重放未变的整库；如其成本或输出量超出预期，记录真实瓶颈后改表示或调整范围。

估计成本时计入实际输入生成、变换运输、序列化、保存、读回、独核和后继联合扩张。一个内核很快或母对象仅剩几类，不说明完整路线便宜。若完整必要域与实现已有、端到端测量可承接，就把该域做完，不以“指数复杂”反复推迟等待更强归约；若局部代表变少而后继共同域不变，则回到共同对象重判。

## 5. 采纳、驳回、修改，并做有界复核

本轮结果应立即导向行动。关键引理成立且caller足够时，选定路线并形成可交回的prove首批义务；关键引理有反例时停止以它为前提的分支，保留见证及重启条件；实现错就修实现并核受影响域；更强条件能排除失败模型时，把证明这些条件列入首批任务。无益松弛被证明恒等时，封存这一特定方法，不推断所有方法都失败。

修改触及reviewer指出的关键逻辑时，将**新增推导、实际探针和精确差异**送原session作一次针对性复核，问原关切是否解决及剩余条件；材料未变不再审。通常一轮提出、实作和一轮有新证据复核就能交接；新结果暴露不同的实质问题时，可在本次探索预算内另开一轮。此边界控制重复审阅，不限制仍在产生新数学事实的研究。

若需要补文献，将具体问题交回mathrsi-survey，例如“文献T的联合规范化是否在保持前一步选择的条件下成立”；附当前式子、已查来源和失败见证。只补新链或读关键原证明，收回条件、版本和定位后恢复**同一义务**，不重新启动整题调查。已读材料足够时直接继续数学推导。

同一卡点两轮没有改变证据、未证条件或下一决定，主代理重新比较表示、共同约束和可替代路线，接管具体缺口或重拆任务。原方法仍有明确新工作可继续；纯资源暂停只保留精确断点，不强迫另造理论。达本子调用预算时交接真实未解项与下一最有价值动作，由上游继续已授权的prove、survey或替代行动；不自动暂停Goal，不以轮数耗尽或模型一致结束数学任务。

## 6. 输出可被证明推进直接消费的路线报告

沿用已有报告结构，自然写清以下内容即可，不要求固定模板：

- 当前原题入口、真正要解决的瓶颈，以及复用的文献和领域知识的准确条件。
- 候选方法及关键依赖，哪些已证、哪些进口、哪些待证；共同对象和归约方向。
- 实际审阅记录与原始trace、实施过的推导/探针、输入范围、结果和本轮判断；未完成审阅明确保留。
- 选定路线或为何暂不选择，放弃方法的具体失败与重启条件。
- 首批任务的精确命题、实际输入、允许假设、独占写域、下游用途与本次预算；原题仍缺哪些条件。
- 一个明确建议next：由调用者调度mathrsi-prove、回准备补某条进口，或在当前授权边界保留断点。

若上游调用本技能，报告就绪后立即**返回原调用者**，交实际路径、未证条件和建议的 [mathrsi-prove](../mathrsi-prove/SKILL.md) 首批任务；不在这里再启动prove。若调用者本来是prove中的路线重判，结果返回该prove义务，不另开prove run。用户独立请求路线设计就在该范围收卷；只有明确授权持续全研究，才按开头规则接过mathrsi-research的阶段调度，从后继继续一次。报告是候选路线的可执行交接，不称“原定理通过”。

## 已完成项目中的路线选择

本仓 [ECC原始独立交接§3.3、4.1](../../../development/context/ecc-source/MATH_RSI_DOMAIN_HANDOFF.md)和[旧题人工交接§3](../../../development/context/ecc-source/HANDOFF_FOR_REVIEW.md)记录旧题 `[43,10,17]₂` 不存在的完整结果：启发式发现172份合格且两两坐标不等价的 `[40,7,18]` 母码，与适用的文献“至多172类”合成完整目录；共同合法陪集上的必要pair图全部为空，使所需三行扩张不可能，省去更高阶组合。本工作流据此做两个决定：发现过程无需为验证而改成穷尽搜索；高阶目标先推导便宜必要门，门为空就关闭它实际覆盖的范围。若门非空，再交后继联合约束，不能把pair存在当成最终矩阵存在。[固定母码案例](../../../plugins/ecc/skills/mathrsi-ecc/examples/fixed-parent.md)给出准确输入与消费方式。这些是仓内历史交接的研究操作，未在本次重跑；后续 `[45,11,17]₂` 仍未解，少量核心和快的中间扩张不能升级成该题完成。

该交接§4.2还有一项实际review→action：早期独核只查接受成员与部分区块，reviewer指出它不支持“两套独立全域”说法；项目先做一例不借旧接受集判定的完整替代扫描，测得可承接后扩完172例。路线循环要把此类意见翻译成缺失属性、具体新实现、真实运行和结果比较，不反复索要模型赞同，也不将“全部保存成员重验”改称补完漏删证据。它不是所有项目一律双扫的模板；当前合同需要什么补强，就解决那个尚存疑问。

## 停滞项目中的具体转折：从无益松弛转向共同约束

[Property B 的component案例](../../../plugins/propertyb/skills/mathrsi-propertyb/examples/component-relaxation-stop.md)给出真实转折：21点原超图研究中，新增分量rank预算的DP被证明在活跃域恒等于旧图majorant。应先证明这条恒等式、消费已有失败literal，停止扩大同一size-only DP。下一提案保留实际incidence/Gram或共同附着容量；首批工作是证明这些新约束确由同一个原超图产生，再测它是否排除仍控制旧界的literal。

该案例里排除两份literal仍没有关闭全分支，报告必须同时保存已有结构工具和准确剩余域。这里的通用动作是“证明松弛无收益→恢复共同来源→先接原输入→再决定是否扩算”；Gram公式、边数和参数条件留给插件。其它领域可对应为同一码的多个投影、同一优化解的耦合约束或同一组合对象的边界数据，不强行套用超图数学。
