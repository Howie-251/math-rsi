# 临界整数界：把取等结构变成可接回原题的见证

本参考由 [route-loop](../../mathrsi-route-loop/SKILL.md)、[prove](../SKILL.md) 和 [verify](../../mathrsi-verify/SKILL.md) 在相应义务出现时读取。它强化已有推导、共同对象和带标记连接，不新增第六个解题阶段。领域定义、容量定理和检查器仍由插件提供；无合适插件时直接研究当前对象。

## 1. 从差额确定下一项研究

适用输入是已经得到的严格推导，以及尚差一个或少数整数单位的目标。例如已证整数目标量 `n(H) ≤ B`，当前要证 `n(H) ≤ B−1`。先核 `B` 为整数、旧上界确已覆盖本次全部对象，再令 `n(H)=B` 研究剩余临界层。排除这一层才能得到减一；若只有浮点近似、条件旧界或尚未覆盖的分支，先保留对应缺口，不能直接宣布只剩取等。

route-loop 读取草稿中的**同一实际 H**、旧界、目标、整条承重不等式、进口和最紧失败配置。给 formula-derivation 的任务是重建差额怎样产生：哪些是确切恒等式，哪些是不等式，哪些是取整或放松。选择最可能给出结构的那条链交 prove；不是继续扩大已经达到松弛上限的样本表。

若旧界为 `n+w ≤ B` 且已证 `w≥0`，临界假设 `n=B` 才给 `w=0`。若多个单位仍开，分别说明剩余整数层或用一个确实覆盖它们的论证，不把一个等号层排除推广到所有层。若参数已经变了，先重算当前预算及可达域，不能沿旧参数的等号分类继续。

写链时标出临界假设 `n=B` 在哪一步被使用，区分恒等式本身与临界层额外迫出的结构。若继续追下一层，先把 `n=B−j` 代回原式，重新推导总松弛；它不一定恰等于 j。若确已得到若干非负整数项之和为 1，就按哪一项吸收这一单位分支；带权、实数或取整项按实际允许域处理。原来推出单射、单例或精确覆盖的链节一旦有了空间，就不能沿用该结论。把各支的新差额与仍有效的结构交 route-loop，再选探针。

### 局部见证有多种选择时，能否保留整个集合？

设同一输入上每类都有非空的候选集。若原推导每类只取一个见证，先查把每类的**全部合法候选**放进同一个诱导对象后，容量定理的前提是否仍成立。逐类可选不足以证明并集可用。明确各类如何编号、哪些元素被重复计数、哪些原标记被删除。若各类互不相交，按类多出的点数恰为各类大小减一之和；有重合时按实际并集重算。若共同合法性证不出，保留已有的单见证界。

把这项计数与同一输入上尚未用尽的各项容量写成取整前的恒等式。对临界整数层代入准确的剩余预算：某个非负整数差额的系数大于总余额，就能断定该项为零，即便其他差额仍可为正。若下一层的研究需要严格正的总差额，把所需下界和适用输入明确交给后续证明。限制输入后，按新输入重算见证集及差额，或证明它们怎样随限制变化。

[Happy Ending 的实际推导](../../../../plugins/happy-ending/skills/mathrsi-happy-ending/references/nmrs-higher-bounds.md)保留每个末锁的全部倒数第二点。九参数工作稿在 1,098 点的假设输入上得到 $\rho+\epsilon+6\delta=2$。三项均为非负整数，故 $\delta=0$，四个组成差额同时归零，包括每个末锁的候选集均为单例。剩下两单位仍可分布在 $\rho$ 和 $\epsilon$ 中。

## 2. 逐项回收松弛，并兑现结构

在当前推导正文写出完整链，比如 `M ≤ |image(C)| ≤ |C| ≤ U = M`。逐条指出所比较的集合、映射、上下界来源和共享选择；每一项必须针对同一 H、同一布局或同一组参数。不同最优解各自的等号不能拼接成联合取等。若链的两端不是相等的同一数，这一步就只能给差额约束。

将总差额展开为有限个已证非负项，例如容器少计、供给超额、角色重叠和未使用容量。总和为零才逐项归零；带正系数的项才可被消去，负系数、误差未定或互相抵消的表达式不能如此处理。取整等号通常只给区间条件，必须回到取整前的式子确认，不能推实数原式取等。

随后把等式翻译成能用的数学结论，并补全实际接口。例如有限集合映射 `|image(C)|=|C|` 给单射；`A⊆B` 且 `|A|=|B|` 给集合相等；每个纤维已知非空且总数等于纤维数，才给每个恰一元素。单靠相同基数不能认定集合相同，单靠总量饱和不能推指定配对存在。应写出本次得到的精确覆盖、单例纤维、满核或次序约束，连同它们依赖的临界假设。

作者交回的是这条链、非负性依据及结构引理的证明。prove 亲自代入原 H，关闭真正供给了条件的义务。若作者额外要求条件 C，则去证明 C 或保留条件版本；不将 C 加进原题。原 wiki 中记录适用层、实际结论和失败边界，下次读取实体全文后才能复用。

## 3. 做合法交换，让容量产生实际见证

有了结构后，再提出具体操作。例如从实际子对象 J 删除 D，加入 R 和标记 z，得到 `F=(J\D)∪R∪{z}`。在调用容量定理前，证明 D 确在 J 中、R 与保留部分不交、z 是新元素，以及每个约束在 F 中仍成立。`|D|=|R|` 只有在这些集合关系给定后才证明等数替换。关系、颜色、坐标或边来自同一母对象；不能自由补一个抽象顶点并假设其关联合法。

给领域执行者的任务应包含：操作前对象、精确删除/加入/运输规则、必须保持的条件、容量进口的完整声明、期望的见证类型及最终 caller。直接得到实际 F 和保留性质的证明后，才代入容量。若 F 超过某一**禁特定见证**类别的已证容量，而其它类别条件都仍成立，容量的逆否命题才迫出这个见证。只知道“F 不是该类别”时，不能跳过其它可能违反的条件，断言出现想要的见证。

结构定理可以保证见证存在，不强制枚举才能认可；但必须是 F 中的见证，给足下一步所需的身份与位置条件。如果交换破坏了进口前提，把 F 和具体失效条件返回原作者修操作；有一个不适用的交换只否定这一操作，不是原题反例。

关闭交换后情形所用的排除引理，必须能从当前临界假设和已得结构独立证出，不能反过来依赖本次交换要导出的矛盾。在正文标明证明位置与依赖；书写先后本身不决定是否循环，实际依赖链才决定。对称操作若产生不同的异常角色，分别核其情形。

## 4. 定位见证，接同一组端点

被迫见证不一定经过新增点。先用 F 的实际不交分块与已证次序，列出它的承重点（例如末点或前驱）全部可能位置，证明这些情形覆盖其实际域。每一情形都交一条已独立证明的排除引理，或在另一个实际对象上的容量论证来关闭；遗漏的一块就是仍开放的义务。

容量只给“有 W”时，先列最终 caller 需要的性质：W 是否必须使用新增元素、该元素在端点还是内部、另一端属于哪个集合、能否与已有外部见证共享同一端点或标记。对每项给实际推论，不把“存在某条路径”直接改成“存在我需要的路径”。

一种可复用接口是：已证 K 中无 W，而 `K∪{x}` 中必有 W，于是 W 使用 x；若另有**端点覆盖** C、K 避开 C、且 x 是这份覆盖在新域中的唯一可能命中点，才可推 x 是端点。只有普通顶点覆盖则仅得 x 在 W 上。若又有方向或角色排除，才能定位首端/末端；另一端的归属还要从实际容器或精确覆盖推出。

最后按**刚得到的那个端点 k**选择外部供给，写出同一 W、外部见证和共享端点的连接。多个分别存在的见证不保证共同选择；不能把两套独立匹配或两种规范化直接拼接。若最后需要不交、次序或特定桥关系，逐项供给；原定理允许共享内部点时也不擅自添加不交条件。

作者若只能得到“经 x 的任意见证”而 caller 需要“从 x 到指定容器的见证”，交回的就是这条精确缺口。保留已得容量/结构，改定位或交换；必要时回 route-loop 重判兼容性，不再批量重复无端点信息的饱和检查。

## 5. 验证与返回发生在哪里

prove 将临界层假设、逐项零松弛、实际操作、容量进口、见证定位和原题结算接在当前正文中，交父调用者选择 verify。verify 读实际式子与对象，核上面的关键箭头，尤其角色到实际点的映射、等数但不合法的交换，以及端点覆盖被误写成一般覆盖的位置；还要核定位情形是否穷尽、关闭引理是否循环，以及新整数层是否重算了松弛。局部核验回原 prove 义务；全链候选仍按任务所需的正式审计/Lean范围处理，不自动增开所有检查。

检查失败时返回具体断裂及保持有效的结果。严格反例先说明它否定的辅助引理和实际域；缺临界人口、特定根或其它条件的反例，不能宣称推翻完整原题。小域检查全过也不证明任意规模的兼容性。

默认产物直接写入 `ROUTE_REPORT.md` / `PROOF_DRAFT.md` / `VERIFICATION.md` 的现用段落，不要求为每一步建新表。成熟结构和失败边界及时写当前任务 wiki，由同一义务和后继阶段读回；历史插件 archive 不作新任务可写 wiki。

## 来源与一次实际使用

Happy Ending 的新工作稿通过同一角色覆盖取等链得到单例 owner 和精确端点覆盖，再等数替锁、加共同根，以两个实际诱导域的容量迫出相容见证。它同时保存了“逐点饱和并不足以给跨侧路径”的 11 点反例。具体数学和原文按 [Happy Ending 主技能](../../../../plugins/happy-ending/skills/mathrsi-happy-ending/SKILL.md) 及其 v4 参考读取；本参考不把那些尚未独立接受的工作证明改写成已验收定理。

本轮使用与原始模型讨论见 [v4 维护记录](../../../../development/evolution/v4-20261108/EVOLUTION.md)。通用动作适用与某个新数学结果最终通过审计是两件事；此处提供下一次研究可执行的方法，不声称已经测得新题成功率提升。
