## 实际 edge-local 规则与短 walk 条件

四个方向为 `l0=(1,0,0), l1=(0,1,0), l2=(0,0,1), l3=(1,1,1)`，任意三个线性独立。每条有向控制边 e:u→v，出发port为p、反向port为q，满足：

```
T_e l_p = l_q,  T_reverse = T_e^-1
(u,x) ~ (v,T_e x + λ l_q), λ∈F_q.
```

矩阵依赖实际有向边，不能替换成仅依赖四个全局标签的通用 chart。简单四正则控制器保证最终图简单且度4q，n=q³|C|。

对非反走三步 `x0—u—v—y0`，设 u→x0 的port为i、v→y0 的port为j，中央边为e，最后边矩阵为S，则三列控制矩阵为 `S[T_e l_i | l_q | l_j]`。因此是否满秩只依赖中央边的局部turn `(i,j)`，而不是完整三步矩阵的全局标签。

相邻 controller fibers 不需要满秩 NB3。可在该边前或后插入两步往返，得到共同中心 `T_e x` 的平面，方向分别为 `span(T_e l_i,l_q)` 与 `span(l_q,l_j)`。这些平面包含共同直线；若它们构成完整 pencil，其并覆盖全部 fiber。这允许原控制器的相邻对完全没有NB3路径。

作者的充分条件是：每个有序控制器对（含对角）要么相邻、由pencil覆盖，要么有至少一条 rank-good NB3。F4 时两组三个投影方向位于 P¹(F4) 的五点上，交一、并五；九个局部turn中恰一个rank2、其余八个rank3。原900对证书含780个full-rank路径和120个edge pencil。

小核验重新检查全部120条有向边的逆矩阵、方向相容及局部坏turn；并核对900项pair证书的端点和秩。全部1080条NB3中960条rank3、120条rank2，与作者证书一致。仅检查这些控制器/线性小数据，没有生成1920点图或运行图BFS，见 `local_check.json`。

## 30点控制器的实际因子结构

控制器由10个互不交K3覆盖全部顶点；剩余边是6个C5：

```
(0,20,28,22,9)
(1,13,23,11,2)
(3,21,8,12,5)
(4,25,14,29,18)
(6,15,27,7,16)
(10,19,26,17,24).
```

每点恰处在一个三角形和一个上述五圈中。把六个C5编号0..5，十个三角形分别交于三个不同的C5，所得到的三元块为：

```
013,125,235,234,024,134,035,145,012,045.
```

每对C5恰在两个三元块中共同出现，形成2-(6,3,2)设计。收缩10个三角形则得到10点简单六正则图；完整映射、邻接、因子圈与三角形在 `controller_structure.json`。这些为直接有限图结构，不是对其几何名称或作者发现过程的推测。

它不是line graph：点0的邻点18、20、9彼此无边，构成显式 induced claw。每点只有一个三角形也与“每点落两个三角”的常见 cubic line-graph 结构不同。

普通 exact-NB3 恰缺120个有序对，全部是相邻对；各根只能达到26个目标。780个非邻有序对含对角的NB3路径数分布为1条:498、2条:264、3条:18。因此这里明确使用了 adjacent pencil 条件，不能把这个30点图误报为exact-NB3控制器。

## q3 的确定局部数据与有限线性问题

F4 不是整数mod4，原矩阵不能把系数直接mod3后沿用。q3时 P¹(F3) 只有四点，两组三点要覆盖全部四点，必须交两个方向。故每条有向边九个turn恰有两个坏turn，形成两条不共行列的二匹配，七个good turn。原F4的“九选一个坏turn”证书不能移植。

本轮只完整枚举了这个很小的局部矩阵空间：GL3(F3)共有11232项；固定每个port的 `T l_p=l_q` 后各有432项，其中324项对应两个坏turn、108项对应三个坏turn。符合完整pencil的两个坏turn共有18种pattern，每种都有可实现矩阵。`q3_local_patterns.json` 为四种port分别保存18种pattern及一个实现矩阵和其逆。对72个代表逐项核对四平面并为27点，且反向坏turn恰为转置；CPU共0.657秒。

对给定新控制器 C，可以给每条无向边e设置18个one-hot二元变量 z[e,k]，表示选哪个局部pattern，反边使用逆矩阵/转置pattern。对每个非邻有序对含对角，要求至少一条NB3的中央turn不落在对应坏pattern。这个问题不需要先搜索任意3×3矩阵。具体数据约定见 `q3_linear_problem.json`；本轮没有解30点或其他阶数的全局one-hot问题。

## 为什么本证书框架不能用32/33点越线

root提出的计数界与已核对的局部条件吻合：每条有向中央边有七个good turn，四正则n点图共有4n条有向边，所以good NB3总数恰28n。n(n−4)个非邻有序对含对角各需至少一条good；每个对角的good闭三步与其逆向是不同路径，rank相同，故对角至少需两条，额外至少n条。因此：

```
28n ≥ n(n−4)+n = n(n−3),  即 n≤31.
```

这里只用反走的秩相容，不假设三角路径循环移位保秩。此界适用于当前“相邻靠pencil、非邻靠单条满秩NB3”的完整证书框架，不是所有q3图的上界。

超过810需要n≥31，所以本框架仅剩n31（最终837点）。n31若可行必须饱和全部计数，good-NB3计数矩阵为 `G=J−A+I`：对角二、相邻零、其他一。于是对固定31点控制器，可直接把上述one-hot模型强化为逐对计数等式；62条无向边各18态，共1116个二元变量。这个确定线性数据问题已交root，未启动controller31搜索。

原30点的互不交三角factor要求3整除n；保留这种factor架构且满足n≤31时最多仍为30点。若同时保留六个/其他数量的五圈factor，还要求5整除n。故31点必须改变原因子结构，例如允许覆盖顶点的三角形重叠；不能只把原30点实例默认扩为31/32/33点。任何新结构仍须单独检验所有非邻控制对和边pattern的可行性，源实例不会自动保证这些覆盖。本轮未恢复旧32/33三角端口profile，也没有做新控制器搜索。
