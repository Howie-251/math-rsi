# 从 Rajiv252 边表恢复的胞元生成规则

来源仅为项目已有 `research/ddp/second_mechanism/rajiv252.edges`。本次没有下载、BFS、哈希、参数搜索或新的下界声明。结构恢复实际 CPU 为 0.034981 秒。

## 检查结果

把每个 C 点（147–251）的两个 A 邻点（0–41）投影成一条边，恰得七个互不相交的 K6，共 105 条不同的边。胞元 u=0,…,6 的 A 点依次为 `{6u,…,6u+5}`。B 点（42–146）的诱导图恰为 35 个 K3。

每个 B 三角形经其九个不同的 C 邻点恰触及三个 A 胞元；在每个胞元内，对应三条投影边构成 K6 的一个 perfect matching。35 个三角形对应七胞元的全部 35 个三元组，各出现一次。

每个 C 点在三个不同的 B 三角形各有一个邻点。若其所属 A 胞元为 u，从这三个三元组删去 u，所得三个二元组恰为另外六个胞元的一个 perfect matching。每胞元的 15 个 C 点穷尽其余六元集的 15 个 perfect matchings。

## 完整组合坐标和边规则

令 U={0,…,6}。在六元集上，把三个不交二元组组成的 perfect matching 记为 S；把五个这样的 S 恰好分割 K6 的全部 15 条边的集合记为 P，即 K6 的 one-factorization。每个六元集恰有 15 个 S、六个 P。

* A 点为 `(u,P)`，其中 P 是 U\{u} 上的一个 one-factorization。共有 7×6=42 点。
* C 点为 `(u,S)`，其中 S 是 U\{u} 上的一个 perfect matching。共有 7×15=105 点。
* B 点为 `(T,M)`，其中 T 是 U 的三元子集，M 是 U\T 上的一个 perfect matching。共有 35×3=105 点。

所有无向边由以下规则给出，没有额外边：

1. `(u,P)` 与 `(u,S)` 相连，当且仅当 S∈P。
2. 固定 T，将其三个 `(T,M)` 两两相连，构成一个 B 三角形。
3. B 点 `(T,M)` 对每个 u∈T，连接 C 点 `(u,{T\{u}}∪M)`。

每个 A 点有五个 C 邻点；每个 C 的 S 恰属于两个 P，并有三个 B 邻点；每个 B 有两个 B 邻点、三个 C 邻点。因此图为 252 点、630 边的 5 正则图。按这些规则生成的边集合已与来源的全部 630 条边逐条集合比较，完全相等。这是从边表得到的完整组合生成规则，并未恢复作者原始 A7 置换生成元或其轨道构建代码。

## 显式映射和全部对应表

`coordinate_tables.json` 保存全部源编号到上述坐标的映射，以及七个胞元、35 个 B 三角形、每个三角形在各胞元的三条投影边、每个 C 的两个 A 端点和三个 B 三角形：

* `A_cells`：七胞元及源 A 编号。
* `B_triangles`：全部三角形、胞元三元组及分胞元 C/投影边。
* `A_vertices`：42 个 `(u,P)` 及 C 邻点。
* `B_vertices`：105 个 `(T,M)` 及 C 邻点。
* `C_vertices`：105 个 `(u,S)`、A 端点、B 邻点及三角形编号。

例如 B42 对应 T={0,1,6}、M={{2,3},{4,5}}，连接 C147、C173、C237。C147 对应 u=0、S={{1,6},{2,3},{4,5}}，两个 A 邻点为 2、5，三个 B 邻点为 42、49、132。

`regenerated252.edges` 是以上组合规则重建的完整源编号边表，首行为 `252 630`。`recover.py` 保存全部有限恢复和等边检查步骤，`RESULT.json` 保存计数及实际 CPU。

## 七胞元限制的准确范围

对于保持本次 A–C 投影胞元、C 的三个 B 邻点、以及每个 B 三角形恰触及三个胞元这些条件的模板：从属于胞元 u 的 C 点 c 出发，在四步内到达另一胞元 v 的 A 点，必须先在至多三步内到达 v 的 C 点。能换胞元的路径只能是 C–B–C 或 C–B–B–C，且 B–B 步留在同一 B 三角形。因此 v 必须属于 c 的三个邻接 B 三角形的胞元三元组之一。每个三角形至多提供两个其他胞元，合计至多六个；若要求 D≤4，则胞元总数至多七。当前图恰在每个 C 处以三个不交二元组覆盖其余六胞元。

这个结论仅限制上述胞元/三角形模板，既不是一般 (5,4) 图的上界，也没有排除改变 B 结构、度分配或其他类型边的构造。本次没有寻找这些改变。
