# H9 projected guard diagnostic: one static code and scope review

Verdict: VALID for the stated saved-column experiment. This is a same-family static read, not a rerun, an external review, or a new validation of the original graph/balls.

Inputs are the 30 completed D12 mandatory neighborhoods on final42402, their saved `missing` target order, `representatives` guard order and `.masks.u64.bin` files. The original writer in `h9_redei15/production/cover.cpp` writes one little-endian uint64 row per representative. The loader uses exactly `mask_words_per_row * 8` bytes per row, checks the full byte count, and interprets bit j as `missing[j]`. The two interval masks partition the whole saved missing list: original exterior `[41356,42342)` and project additions `[42342,42402)`. They are target projections, not newly computed source balls.

The original native preparation retains one actual eligible guard per identical full missing-target mask and omits zero masks. Neither operation loses projected feasibility: guards with identical full columns remain identical on every target subset; a full zero column stays zero. The new projection may deduplicate again without harming a cover of size at most two. A pair of equal projected columns has no more coverage than either alone.

For target bitset T and projected first column A⊆T, a second column B completes the cover exactly when it covers every bit of `T ^ A = T\A`. The script constructs, for each target bit, the bitset of all columns covering it and intersects those bitsets. Therefore the search is exact for budgets0,1,2, after testing one-column covers. A first column cannot appear as a spurious second column when it has a missing target. Literal witnesses are distinct and are checked against the saved original columns; auxiliary support indices never become graph vertices.

The completed result is inherited from `H9_PROJECTED_GUARD_RESULT.json`: 30/30 cases, no unattempted case; original-exterior-only feasibility0/30; project-addition-only feasibility10/30 (the remaining20 have zero guard budget); all five two-guard cases still fail on original exterior alone. CPU0.703871411. The existence prediction was frozen after the old missing-label classification but before this projection computation, and is REFUTED. The earlier label split itself remains a post hoc read-only classification, not a preregistered prediction.

This shows that the saved mandatory neighborhoods cannot be rescued merely by ignoring project-added targets while keeping the same final-graph guard domain and budget. Removing vertices cannot shorten paths to fixed surviving exterior targets. It does not classify the graph obtained by removing additions and then using newly freed guards, changing the mandatory neighborhood, adding other edges, or jointly rearranging extensions. Separate feasibility of two target classes would not imply a common guard set; here the original-exterior class already blocks every case.

No new graph, source BFS, ball construction, solver call, or numerical re-evaluation was performed in this review. The actual diagnostic reuses cached columns and is appended to the existing stable-triangle-twist experiment, not counted as a new method or lower bound.
