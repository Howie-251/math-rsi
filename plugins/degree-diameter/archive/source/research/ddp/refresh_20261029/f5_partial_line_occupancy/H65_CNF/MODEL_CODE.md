# H65增量CNF：仅准备，未求解

本目录不修改旧模型、same-fiber模型或其变量编号，也不启动solver。旧3750个keep变量不变：旧顶点v对应变量v+1。父增强模型变量上界315221。

本次新变量范围为315222..333551，共18330。30个明确high变量先分配为

    h_a = 315222+a，a=0..29。

其余18300个变量从315252开始，全部用于各层精确求和与比较门。每层独立平衡二进制加法，输入为其125个keep变量，保留全部进位；不截断高位。复用旧retention prepare.py中的exact xor、majority、AND/OR及add_bits定义。常数比较同旧代码，从低位扫描65的二进制位构造exact >=65，再以两条子句把h_a与该比较结果双向绑定。因此h不是单向阈值见证，而是

    h_a ↔ sum_{i=0..124} keep[125a+i] ≥65。

## 四个独立增量文件

每个文件有自己的DIMACS header，使用同一完整变量上界333551；它们是增量片段，不包含父模型。合并时只保留一份最终header并相加子句数。

| 文件 | 子句数 | 作用/依赖 |
|---|---:|---|
| high_flags.added.cnf | 76290 | 全部精确求和、比较、30个h iff绑定 |
| h65_edges.added.cnf | 19500 | H65的高高external边整线/运输关系；依赖high定义和H65引理 |
| exists_high.added.cnf | 1 | h0∨…∨h29；仅在总保留数≥1921时使用 |
| not_all_high.added.cnf | 1 | ¬h0∨…∨¬h29；依赖PROOF.md第5节全高排除 |

四者全用时新增95792子句。未据此生成一个全局可运行合并模型，由root审阅后决定是否合并。

## 条件边关系的准确编码

从实际参数取无共同控制邻点的external边，按u<v选一个方向u→v,p，共30条。共同guard为¬h_u、¬h_v。任何条件等价a↔b都直接写成

    ¬h_u ∨ ¬h_v ∨ ¬a ∨ b；
    ¬h_u ∨ ¬h_v ∨ a ∨ ¬b。

每条边包含：

* source层的25条ell_p线，每条选编码最小点为基点，与其余4点绑定：200子句；
* target层的25条ell_inv(p)线，同样绑定：200子句；
* 全部125个x，keep_u[x]↔keep_v[T_p x]：250子句。

合计每边650条四literal子句，30边共19500。两个high有任一个为false时，整组子句自动满足，不强加整线或运输。目标整线条件虽可由其它两部分推出，仍按授权明确保留。

## 无solver校准

CALIBRATION.json记录：

1. AND、OR、XOR、majority的40个完整输入/输出真值状态，CNF恰拒绝错误输出；
2. 第一层125位求和的全部count=0..125前缀常量赋值，以及count64、65的反向后缀赋值，共128组；
3. 逐门确定求值后，sum bits重建值均等于输入count，正确h满足全部该层子句，翻转h均违反绑定。

30层由同一门模板仅平移keep编号生成。校准未使用SAT、图BFS或新图。准备及校准CPU0.802707212秒，1worker，小于10秒。

## 合并时的编号边界

本片段按明确要求从315221之后分配。若另一个独立增量（如same-fiber）也从315222开始，两个新变量范围会冲突，必须由合并方统一重编号其中一方的新增变量及其元数据；1..315221共同父变量保持不变。不能把冲突编号的两个片段直接拼接。本目录没有改动另一代理的文件。

数学依赖、有限商证明和64/65边界反例见上级PROOF.md及BOUNDARY_COUNTEREXAMPLE.json。最终是否合并及任何求解均由root另行决定。
