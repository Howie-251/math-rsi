# 391 正权组：完整 K2 整数覆盖 CNF

本目录唯一准备程序是 `prepare.py --prepare-only`，没有 solve 入口，也不导入或
运行旧 K2 driver。已实际完成：PID **2054054**，exit **0**，准备
**4.008762751 CPU 秒**。`PREPARE_TERMINAL.json` 保留该 PID 和完整计数。
尚未调用求解器；后续启动由 root 审阅决定。

## 固定池和 selector 映射

从已精确全验的 `../d14_K2_fractional_capacity/EXACT_GLOBAL_WITNESS.json`
读取所有分子大于零的组，按原 group ID 升序得到恰 391 组。其中 379 组容量 1，
12 组容量 2。没有增加零权组或删除正权组。

局部组下标 j 为 0..390，A 侧变量为 `j+1`，B 侧为 `392+j`，共 782 个 selector。
`SELECTOR_MAP.json` 每项同时保存原 group ID、两 selector、原成员 column/旧顶点
标签/spare，以及该组的精确分数分子。`selected_group_ids.u32le.bin` 保存相同顺序。

组内完整有序 `(R3,R4)` 签名相同，故同一 helper 同组选择多个 port 没有覆盖收益，
删除多余选择只释放度数与容量。这不是把全部组只能分给一侧：容量 2 组仍可双选。
组约简的纸面独立核对已确认该规则与下述实际重建保全。

## 度数与端口容量

每侧的 391 个 selector 使用旧 K2 已用的顺序阈值编码，阈值为 1..13。
对每个前缀 i 的阈值变量 s[i,k]，子句强制选中第 i 项蕴含 s[i,1]，已有阈值
向下一前缀传播，且选中第 i 项并达到上一阈值 k−1 时蕴含新阈值 k；若上一前缀
已达 13，则第 i 项禁止选中。

这只使用阈值的正向蕴含，但 existential-equivalent：任何超过 13 的 selector
赋值必触发 overflow；任意不超过 13 的赋值，都可用真实前缀阈值扩展满足所有
辅助子句。两侧各 5083 个辅助变量，共 **10166 个辅助变量、21086 条计数子句**。
不强加恰 13，也不添加 A/B 顺序或其他对称限制。

每个容量 1 组另外加入 `¬A_j∨¬B_j`，共 **379 条**。容量 2 组无该互斥。
固定新 helper 边占每个 helper 的一度，所以各侧至多 13 个旧端口给新度至多 14；
这条新边不消耗任何旧顶点的 spare。

## 全部目标行

原完整转置缓存每目标有 3589 个组位。本程序只按上面的字面组序取 391 列，保留
全部 94186 个目标，生成两份每目标 7 个 little-endian uint64 的完整缓存：

- `target_R3_support391.u64le.bin`
- `target_R4_support391.u64le.bin`

每目标 t 的两条原始覆盖行分别是

```
OR_{g:t∈R4_g} A_g  OR  OR_{g:t∈R3_g} B_g
OR_{g:t∈R3_g} A_g  OR  OR_{g:t∈R4_g} B_g。
```

因此每个选中解恰表示两个新根到全部旧目标的 D≤5 覆盖条件，不是 LP 的加权行。
每条行用完整 782 位正 literal 集合表示，只按整数精确相等合并。原始 **188372**
条双侧行合并 **514** 条重复，实际保留 **187858** 条；没有支配删除或稀行抽样。

`COVERAGE_ROWS.json` 保存每条唯一行的首个 `(side,target)` 代表与重数；
`target_side_to_coverage_row.u32le.bin` 保存全部 188372 条原行到唯一行的映射，布局
为先 A 侧 94186 项，再 B 侧 94186 项，每项是零起始 unique-row ID。
唯一覆盖行在 CNF 中紧跟 21465 条计数/容量子句，其次序与 row ID 相同。

最终 `model.cnf` 为 **10948 变量、209323 子句、14268440 个 literal occurrences**。
`model.body.clauses` 保存同一正文；`MODEL.json` 保存准备与未来预算说明。

## 真 SAT 后的字面重建接口

这部分是接口说明，准备程序没有执行任何候选检查或读取源边表。

先解析 782 个 selector；核每侧≤13、容量1组不双选。随后用这里两份完整限制缓存
逐个目标检查上述两个 OR，不能用 LP 证书代替整数候选覆盖检查。

对选中组按 `SELECTOR_MAP.json` 重建实际旧端口：

1. 只一侧选择：取组内任一 spare≥1 的成员。
2. 两侧选择：若存在 spare≥2 成员，可将同一旧顶点分别连两个不同 helper；
   否则选两个不同的 spare1 成员，分别分给 A、B。

`groupcap=2` 保证第二种选择可实现；组之间成员互不重叠，所以不产生跨组容量冲突。
同一旧顶点连接两个不同 helper 不是重边。只保存可重建的 A、B 和 cached-cover
验收后，root 再独立检验实际完整新根。这里不生成新图。
