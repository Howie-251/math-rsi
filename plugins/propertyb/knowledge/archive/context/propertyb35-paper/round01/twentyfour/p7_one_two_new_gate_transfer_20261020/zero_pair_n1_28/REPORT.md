# I2、28单迹库存：同权三蓝及蓝对fallback的确切停点

本稿保留原两种快捷选择的失败诊断，数值和失败源不变。该实际库存随后由[补集覆盖与共享单迹度解析修复](ANALYTIC_REPAIR.md)补齐；新证明不声称这里的原权或fallback全域通过，也不依赖一个一般12正门。

本轮只研究实际库存 $(n_2,n_3,n_4)=(0,2,3)$。它满足2n3+3n4=13、n1=20+n3+2n4=28；不是此前27单迹的两个无J库存。本稿保存必要P源下现有选择接口的明确边界，不是原H或signed系统不可染反例。

## 必要域与原权

P七点全部八度、L17点全七度、两内部missing为01,12或01,23。ci为内部频率、ai为两个三迹频率、bi为三个四迹频率，实际

$$u_i=8-c_i-a_i-b_i\ge0,\quad\sum_i u_i=28.$$

必要条件为P点对由内部／高迹覆盖，以及4ui+2ai+bi≥17。三个quad多重集每形原始7770份，内部稳定子群各48，得到332／298轨道，合630位置。`QUAD_ORBITS.py/json`保留全部15540像键和实际运输；此轮未执行该全域第二运输核验，不把630位置等同于全部高源已验。

原三蓝候选排除等于完整高P3者，λQ=(12−ΣQ ui)+；W为候选权，M按不同高迹漏事件加权并界。对红四补集S，权应是(ΣS ui−16)+，不是27单迹时的−15。

## 原权首失败：有蓝对可修

`GENERATE.cpp`原样保持同一权，首非正即停，结果`GENERATION.json`：仅完整完成job0，在job1第27份必要源出现Δ0，未展开后续域。

源为相邻missing01,12；三quad为0123、0123、0124，两个P3为156、456。七点ui全4。所有必要条件均满足，但全部25个proper三蓝私和12，所以W=M=Δ0，没有低私和三蓝。

它有proper蓝对14，实际8P4/0T20B、L17，可用旧八正门修复。`VERIFY_FAILURE.py`逐21蓝对／35三蓝及35原迹独立检查，`FAILURE_CHECK.json`为PASS。原失败和原公式没有被fallback结果覆盖或修改。

## 解析pairgate和完整续跑的首边界

若存在命中全部内部／高迹的蓝对Q2，则cQ≥2、hQ≥5，故m=16−cQ−hQ≤9。真实signed系统是mP4/0T/(28−m)B4：m≤7由七门，m8的20B由L17八门，m9的19B由九门接受。因此新增的合法判据是“存在proper蓝对，或原三蓝Δ>0”，不是将两候选族的权擅自相加。

`PAIR_FALLBACK.cpp`完整沿原必要域续跑，逐源先试这个解析蓝对门，没有蓝对才要求原Δ>0。每个已接受源在`FALLBACK_NECESSARY.tsv`保存自己的pair或三蓝、实际m、原Δ/W/M。原三蓝失败被蓝对救回者仍保留其非正Δ，没有改写成原权全过。

续跑完成前364个quad位置，在job364第10359份已测试必要源（含失败）出现首个**无proper蓝对且Δ≤0**源，立即停。CPU约0.011秒；未跑LP、未换权。准确计数和接受方式在`FALLBACK_GENERATION.json`。没有声称全部630位置或完整必要高域已通过。

## fallback首边界的明确结构

源的内部missing为01,23，即内部23456、01456；高迹为

$$P3:126,036;\qquad P4:0123,0245,1345;\qquad u=(4,4,4,4,4,4,4).$$

（以mask表示，内部124／115，三迹70／73，四迹15／53／58。）必要PL容量和P点对覆盖全部成立。所有21蓝对都至少漏一内部或高迹；全部22个proper三蓝私和均12，故原权全零，Δ0。该源任何proper三蓝留下的是

$$12P4,\quad0T,\quad16B4,\quad |L|=17,\quad D7.$$

例如Q=012。它超过当前用到的≤11正四纯门；不代表这个signed系统不可修，也不证明这些P源可共同实现原H外部布局。

蓝对失败有透明的补集覆盖几何：两个P3的四点补集为0345、1245，它们的两个K4共享边45；三个P4补集为456、136、026，它们的三角边与内部missing01、23一起恰覆盖K7全部21对。独立脚本直接核了这个覆盖并和零proper蓝对，无需假设抽象权ui任意。

`VERIFY_FALLBACK_FAILURE.py`只读取明确失败源，不导入生成器，独立计算c/a/b/u、直接star外部容量、P点对覆盖、21蓝对、35三蓝以及所选Q的全部35原迹。结果`FALLBACK_FAILURE_CHECK.json`为PASS，签名精确12P4/0T16B；没有隐藏小正或负三。

因此仅靠本诊断两入口不能声称n1≥27全闭；当时n1=28的I2 $(0,2,3)$是明确单独义务。后续解析修复利用实际共享单迹度完成它，原失败仍不能当原题反例或被改称原快捷门成功。
