# 任意覆盖二十点的简单六四元星：统一平衡计数

## 定理与范围

设L0,…,L5是20点集V上的六个互异四元集，且它们的并恰为V。在D=C(20,10)=184756份十红十蓝染色中，令C表示“不会同时有全红的某Li和全蓝的某Lj”，等价于至少一种颜色没有单色link。那么

    |C|≥164896。

此下界可取到。最紧系统的重复点支持在六个link索引上的形状是两条相邻二重pair：01,01,02,02。它不需要先排三条平行重复pair，也不需要原点度上界、A1角色或外部超图条件。

特别，对任21点简单五元H、覆盖所有点对、任意指定六度中心x，删x的六条边给满足上述条件的六个link，因此其星单独定义的C都有同一下界。本定理只计这份星的颜色事件；不导入A1删星度谱、Hbar矩／rank，也不据此宣称原H／全21／36可染。

## 1. 总重复成本四给五种完整表示

每个实际点u∈V的link出现次数m(u)≥1，且Σm(u)=6*4=24。于是

    Σ_u(m(u)−1)=24−20=4。

只考虑m≥2的重复点。每点成本为正整数m−1，故重复点多重数只能为

    (2,2,2,2)、(3,2,2)、(3,3)、(4,2)、(5)。          (1)

不存在m6点，其成本五已超预算。分别有4/3/2/2/1个重复点；单位点数为16/17/18/18/19。

把一个重复点u表示为其出现的link索引支持Su⊆{0,…,5}，|Su|=m(u)。相同多重数的重复点无序，**允许相同支持重复出现**，因为它们可为不同实际点。六个link索引有标签；这一步忘掉20点的具体名字，并非忘掉原边索引或要求H有自同构。

一份重复点支持多重集决定每块的重复占位，必须≤4；其余槽分别补入仅属于该块、且各块间互不相同的单位点。补点总数是24−Σ重复点m，加重复点个数给20。任何实际星均可按同一支持和各块单位点作实际点重命名，故此表示无损覆盖所有实际星。计数C对20点的重命名不变。

下表为相同多重数点无序时的完整原始标签数：

|重复多重数|完整raw数|容量／simple后有效数|
|---|---:|---:|
|2,2,2,2|multichoose(15,4)=3060|3045|
|3,2,2|C(6,3)*multichoose(15,2)=2400|2400|
|3,3|multichoose(20,2)=210|210|
|4,2|C(6,4)*C(6,2)=225|225|
|5|C(6,5)=6|6|
|合计|5901|5886|

容量条件逐标签检查；事实上重复点至多四个，所以各块重复占位自动≤4，不额外丢掉标签。真正simple筛选恰丢15份：若Li=Lj，它们的四个点均重复，且每点至少成本一，已花满成本四；所以四点全为multiplicity2、支持都恰{i,j}，没有其他重复点。反向四条同pair支持确使两link相同。因此只排四重平行的15个pair，不排三重平行，也不施加任何已知四核修复。

## 2. 真S6轨道及精确两色容斥

S6在六个原link索引上作用，逐支持Su运输并排序同类重复点。这保留容量、link互异和重复分型，也保持所表示星的C。只需要它作为星表示的重标号，不声称它是完整原H的自同构。

对非空索引集I,J，令R(I)=并_{i∈I}Li，B(J)=并_{j∈J}Lj。若这两个并相交，同时强制前者红、后者蓝的事件为空；否则恰有

    C(20−|R(I)|−|B(J)|,10−|R(I)|)                     (2)

个十红点集满足它。任何不合法二项式取零。全红link并事件与全蓝link并事件分别作容斥，得到“两色都有单色link”的精确整数计数

    Both=Σ_{I≠∅,J≠∅,I∩J=∅}
      (−1)^{|I|+|J|} 1_{R(I)∩B(J)=∅}
      C(20−|R(I)|−|B(J)|,10−|R(I)|)。                (3)

I,J同含一个link时事件本来不可能，所以只写不交索引集不漏项。所求C=D−Both。只有六个link的有色索引选择，至多3^6项；未枚举H或给每个代表枚举184756染色。

完整真群结果如下。每种最紧代表的支持mask取第0位为link0；mask3表示01、mask5表示02、mask7表示012，依此类推。

|重复多重数|有效标签|S6轨道数|该型C最小值|最紧支持masks|
|---|---:|---:|---:|---|
|2,2,2,2|3045|20|164896|3,3,5,5|
|3,2,2|2400|13|166792|3,5,7|
|3,3|210|4|167512|7,7|
|4,2|225|3|171134|3,15|
|5|6|1|177176|31|
|合计|5886|41|164896|唯一最紧轨道01²＋02²|

RESULT.json保留全部41代表、每份完整轨道成员、重复占位／link masks、C精确数及原始simple排除键。这些数值不是实际H类的数量：它们是六块有标签、20点名字已遗忘的完整星表示及其真群轨道。

## 3. 不排三重平行仍保留旧最小值

旧四个二重点且每pair平行重数≤2的域只含2835标签／18轨道。当前全(2,2,2,2)域额外加入三重平行、第四边邻接或不邻接的两轨道：

|重复支持形状|新增标签数|C|
|---|---:|---:|
|01,01,01,02|120|165592|
|01,01,01,23|90|166462|

它们都高于164896，所以无需通过低四核修复先排它们。其余四种多重数分型的最小值也都严格高于164896；因此旧最坏下界在整个允许星域仍然普适。

最紧星可以明确写为

    L0={0,1,2,3}, L1={0,1,4,5}, L2={2,3,6,7},
    L3={8,9,10,11}, L4={12,13,14,15}, L5={16,17,18,19}。

它有20点并集、六link互异、总成本四。第二种独立容斥给“无全红link”计139496，“两色都无单色link”计114096，所以

    C=2*139496−114096=164896。

这同时证明下界可取到，而非仅一个方便的松上界。

## 4. 两种完整域生成及独立计数

GENERATE.py按式(1)五分型使用支持多重组合生成全部5901 raw键，逐键检查容量／link互异，保留5886键。它用720个S6真作用产生全部orbit成员，并以(3)计算每代表精确C。

VERIFY.py不导入发现生成器。它依次遍历全部56个允许支持mask，直接用总excess预算四作非负整数重数递归，另生全部raw／valid／duplicate键。随后用五个相邻换位的BFS生成每代表轨道，逐成员检查与保存轨道相等、各轨道互不交且覆盖全部5886完整键。

其计数公式也独立：先以64项单色容斥求N_R=“无全红link”；再以3^6项求N_0=“没有任何颜色的单色link”；颜色对称给

    C=|no-red ∪ no-blue|=2N_R−N_0。                   (4)

其中每个强制颜色项仍使用(2)，有色并冲突时为零。全部41份式(4)与发现式(3)逐项相同。VERIFY.json保留每代表的N_R、N_0和C，因此可逐行核对，不只保存最小值或PASS字样。

本机实际GENERATE耗0.048072CPU秒，独立VERIFY完整域／群像／另一IE耗0.094227CPU秒，均结束且PASS。没有进行18万染色×多代表遍历，没有whole-H／自由负布局／新锁表搜索。全域概率／覆盖／重标号与实际星连接已在正文明确；新star-only范围待root全文验收及其指定审阅，不继承旧A1范围的模型认可。

复算（仅5886星键及41小容斥）：

```sh
P=context/propertyb35-paper/round01/middle/generic_degree_six_star_count_20261020
python3 -B "$P/GENERATE.py"
python3 -B "$P/VERIFY.py"
```

本定理不把通用星计数与某特定A1 Hbar谱／rank绑定，不自动推广任何whole21／36结论。第五型C177176与29*6006的数值差3002可直接核算，但本稿只声明星自身的C下界。
