# 独立 ECC handoff 的设计增量

2026-11-01。只读完整比较：v2 的 `MATH_RSI_DOMAIN_HANDOFF.md`（266行）、本项目 `MATH_RSI_DESIGN.md`（133行）与 `MATH_RSI_ECC_COMPARISON.md`（110行）。未扩读案例、运行程序、调用模型、写 v2 或改变 Goal。以下为供 Root 判断的建议，未修改主稿。

总体没有架构冲突。原量词、构造／否定两终点、共同对象、成员正确与无遗漏分开、先诊断再扩算等，现稿已经吸收。现稿也没有误把 base 定义成泛化搜索器：DESIGN §1、§4 明确它不是数学裁判且不假设自动 verifier；COMPARISON §7 明确旧搜索引擎只是可选后端。无需为重复共识新增一层架构。

## 最多四项值得补入的具体差异

| 项目 | 独立 handoff 的新增具体性 | 当前稿与建议落点 |
|---|---|---|
| **1. 验证能力应绑定“本次义务”，不能只绑定题目或领域。** | §1、§3.2–3.3、§7.3：同一题的显式矩阵验距、F成员检查、F无遗漏、pair拒绝、CNF不可满足、编码无损性是不同能力；存在构造 verifier 不等于全题已有 verifier。§4.4 的固定Q实例只有一套完整F生成、pair两方法还共享循环，照样可在准确范围内审计；不应把旧题“两套全域”升级成通用最高成本组合。 | DESIGN §1、§4和COMPARISON §2、§6已概念覆盖，但可在“验证接入”加一句：**每次调用列明待核销义务、实际属性和剩余数学连接，选择足够的证据组合；不设题目级 `verifier_pass`。** 不要求重造统一数值评分器或让base判定数学。 |
| **2. 停止原因与重新启动条件应成对表达。** | §4.5 的分类试验因预测64 CPU秒超过本批40秒而停止，这是资源决定；§4.6 的九局部域全部非空则因未关闭输入而停，下一次要有共享H的实质耦合。二者不同。§4.3又说明已确认可完成的批次应真正做完。 | DESIGN §3、COMPARISON §5已允许重新决策和新条件重试，但尚未明确区分：**已闭域**保持复用；**无信息增量**需新的数学／表示理由；**预算不足**可在获得相应授权和新预算后用同算法继续，不必假造新数学。资源停机不等于禁止路线，也不能由base自行扩大已冻结预算。 |
| **3. 存储、产物粒度和读回应进入成本判断。** | §4.3明确新批留下约125.836 GiB、824,370个case证据文件；§5.2要求CPU、墙钟、存储、调用预算。文件组织本身可以成为后续核验和交接的成本。 | DESIGN §3和COMPARISON §5已讲端到端成本，但未显式提存储／文件数量。可把“准备、计算、输出、独核”补成包含**必要证据载荷、文件数量及读回代价**；仅在它影响本次选择时报告，不强制每次另写资源表或照搬旧目录组织。 |
| **4. 历史复放的防答案泄漏要落实到执行者输入。** | §8不只说使用当时材料：执行者不能拿到本handoff、完整wiki或最终报告；准备者裁出当时输入，冻结具体文件版本；目录创建时间不能保证文件未后补。给出四个不同能力的小断点，且不要求全跑。 | DESIGN §6、COMPARISON §8已有不泄漏后来答案的原则，缺少这个操作边界。首次小试应由准备者制作最小输入清单与版本快照，执行者只看该包；保存全wiki的研究工作区与测评执行输入分开。无需复杂平台，先选一个与待检验机制一致的断点。 |

第1项是现有原则的必要操作化，第2–4项是更具体的调度与评估补充。没有发现需要推翻三层拆分、把base改成搜索器，或强加Lean／完整分类／统一评分的新证据。是否采纳仍由Root结合原稿和用户目标决定。
