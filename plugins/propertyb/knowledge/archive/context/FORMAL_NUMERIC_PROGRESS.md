# NUM：有限数值义务的 Lean 内核核验

`formal/Aris4Math/Numeric.lean` 核验了证明所用的全部 21 个成功数值剖面，
并保留两个严格大于 1 的诊断剖面。这里的结论是 **NUM 已由 Lean 内核核验**，
不是主定理 `Aris4Math.Target` 已在 Lean 中证明。

## 实际证明了什么

每个 `*_value` 定理的左端是 `totalBound profile`：Lean 从静态的顶点数、锁位和
精确类型计数出发，重新计算每个位置的单边最后点界 A、第一点界 B、全部有序类型对界 C，
计算 link 扣除 D，再求 `min A (min B (C - D))`，最后对全部位置求和。
右端的分数是待证明的结论，没有作为假设传入。

- 23 个剖面共 534 个位置，涵盖 `results/reproduced_bounds.json` 的全部行。
- 五个有修正的分支共有八个中心。`linkSlots` 对不同类型对用乘积容量、相同类型用二项式容量，
  每一槽位的权重为两个方向之和。`deduction` 排序后取最便宜的 q 项，零权重参与排序。
- 八个 `*_link_*` 定理分别核验 q 的数值、槽位容量足够、扣除量的精确值，以及 `0 ≤ D ≤ C`。
- 五个 `*_base_value` 定理还核验相同剖面关闭修正后的原始上界。最终值直接在扣除后重新取最小值，
  不把 C 的下降无条件当成总界的下降。
- `all_successful_values` 将全部 21 个成功剖面的 `totalBound < 1` 合成一个定理；
  `v23_67_gt_one` 与 `v25_K6_4_gt_one` 明确保留两个失败诊断。
- 每个 `*_valid` 定理检查本剖面的锁位范围、严格递增及无重复，类型的规范排序、取自锁位、
  大小及自由点数范围、正计数与总边数 32，以及 cap 的数值适用形状。

这些是完整的封闭有理数计算义务，不是抽样超图、抽样排列或仅核验末尾分数小于 1。

## 实现与公式对应

| Lean 定义 | 数学对象 |
|---|---|
| `EdgeType.locks` | 边类型所包含锁点的实际排列位置，采用递增列表 |
| `EdgeType.count` | 精确类型计数 ℓ_T |
| `freeCount` / `leftCount` / `rightCount` | N、a_k、b_k |
| `edgeWeight` | P2a/P2b；先检查锁点相对中心的位置兼容条件 |
| `pairWeight` | P3b/P4b；先检查交集类型、左右兼容及容量；无额外 r·q 因子 |
| `pairCount` | ℓ_T(ℓ_U−[T=U])；仅 v20 使用外部结构证明给出的 948 cap |
| `boundA` / `boundB` / `boundC` | P2c/P5b 的有限类型求和 |
| `linkSlots` / `linkQLower` / `deduction` | P6b 双向槽位、P8 数值输入及最低权重扣除计算 |
| `positionBound` / `totalBound` | P7a 扣除后逐位置最小值与总和 |

`binom` 采用 `Nat.fast_choose` 的下降阶乘实现，避免对同一个二项式作庞大的递归展开。
`binom_eq_choose` 对**任意**自然数参数证明它等于 `Nat.choose`，依据 Mathlib 已证恒等式。
分式的除法在 `Rat` 中进行；不是自然数整数除法。

类型输入对应原 JSON 的位掩码：第 i 位映射为 `positions[i]`，计数原样保留。
每个 Lean 剖面前的注释保留原 mask/counts，便于逐条核对。
生成器只读取静态输入和待证分数，不导入 Python 概率计算器，也不把 Python 输出声明成公理。
生成器不是数学信任前提：生成的数值等式须经内核证明；输入和书面结构证明的对应仍须审阅。

## 内核与复现

所有数值等式使用 `by decide +kernel`；严格不等式由等式重写后用 `norm_num`。
`+kernel` 明确使用 Lean 内核归约，不是 `native_decide` 或外部程序验算。
已成功运行的完整检查对 23 个 `*_value`、汇总定理及二项式恒等式打印公理依赖：
全部仅有 `propext`、`Classical.choice`、`Quot.sound`，没有 `sorryAx` 或新公理。
另从已编译模块导入后，对全部 84 个定理打印了公理依赖；有效性定理只需其中两个标准公理，其余也未超出这三个。
可导入模块的 `lake build Aris4Math.Numeric` 已成功，耗时 81.418 秒。

从项目根目录运行：

```sh
export ELAN_HOME="$PWD/.tools/elan"
export PATH="$ELAN_HOME/bin:$PATH"
cd formal
lake build Aris4Math.Numeric
```

如需根据已维护的数值输入重建静态数据，在项目根目录先运行：

```sh
python3 formal/generate_numeric_certificate.py
```

生成器保留 Numeric.lean 中的通用求值器，仅重建标记区的剖面和闭式定理。
Lean 4.24.0 和 Mathlib v4.24.0 与已有工程一致，没有修改工具链或 lakefile。
真实编译日志与耗时记录位于
`.aris/traces/proof-checker/2026-10-06_run04/lean-numeric-build.log`
及同名 `.meta.json`；全部定理的公理审计在 `lean-numeric-axioms.log` 和 `.meta.json`。

## 仍未形式化的数学连接

本模块**没有**从任意 32 边五元超图推出上述剖面之一，也没有将 `pairWeight` 的闭式定义
识别为实际条件排列事件的概率。以下仍由书面证明及对应的其他形式化模块承担：

1. 最小顶点反例约化、全部顶点数范围的覆盖和 20 点 948 cap 的结构证明。
2. 锁点选择、类型计数、K4/K6 分类完备性及七点避开唯一坏型。
3. 随机贪心失败覆盖，以及 P2–P5 闭式与真实有限排列计数的等式。
4. 实际不同坏边对可注入 `linkSlots`、P8 的结构下界及“最便宜 q 槽位”对实际删除量的支配关系。
5. 以上接口与已形式化的有限事件/加权删除语义模块相接，最终推出 `Target`。

NUM 的内核通过不替代这些连接，也不将两个诊断剖面删除出原始数值记录。
