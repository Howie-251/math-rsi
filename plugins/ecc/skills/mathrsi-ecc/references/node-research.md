# 按节点推进 ECC：每次行动先确定归属

本协议由 mathrsi-ecc 在每次新推进、恢复、换方法及收回结果时执行。沿用当前任务的 FORMAL_SPEC、OBLIGATIONS/BRANCHES、NEXT_SESSION 和 research-wiki；不要求迁移目录或新建知识库。短题可把以下字段写在同一段正文。模板见[节点工作包](../examples/node-work-package.md)，结构示例见[分枝与共用计算](../examples/node-research.md)。

## 1. 先回答“这次推进属于哪里”

协调者先读当前节点账本、相关 wiki 实体和原证据，再按对象、量词、目标距离、假设和覆盖范围匹配，不能只搜索节点名称。每次发起推导、搜索或子任务前，保存一份具体归属记录：

- 当前 node_id、原题入口、节点准确谓词，以及此次 task_id。
- 已有结果与本次输入是什么关系：相同、包含、被包含、相交、互斥或未知；给出推导或数据证据。
- 已有结果覆盖哪里，本次新增信息是什么，结果将改变哪个节点的哪项义务。
- 依赖是否成立、同一任务是否在途、是否存在可用检查点；本次产物由谁消费。

若属于已有分枝，继续同一节点。换算法、换代理、换轮号只新增执行尝试，不建立同义数学节点。已有完整排除覆盖本次对象与目标时，引用证据结束搜索派单；若发现具体缺陷，另开有明确缺陷、范围和用途的审计任务，保留原记录及受影响节点，不能借审计重复构造搜索。

若没有直接匹配，必须先确定以下一种归属：

|情况|挂接方式|实质推进前的义务|
|---|---|---|
|已有节点的细分|挂到该父节点|写细分谓词、覆盖理由、是否互斥和未覆盖补集|
|现有局部库之外的新对象|挂到相应“其它/未覆盖”节点|证明不被旧闭合范围覆盖；不能只说矩阵不同|
|多枝共用的引理或计算|建一个依赖任务，关联多个 node_id|明确各枝如何消费同一结果，不复制执行|
|超出原对象域的辅助问题|挂为辅助义务并链接原节点|说明归约方向和如何返回原题，不修改原目标|
|包含/相交关系尚未知|先开归属核对任务|只做所需读证据、消元或归约核对；未澄清前不启动依赖该归属的大扫描|

新想法可以先有归属核对 ID；不能为得到一个新 ID 而伪称它与旧对象互斥。新任务无现成分枝时以原目标为根，先给最小可辩护的划分，未归类部分保留显式 remainder。

## 2. 对象树、证明依赖和执行任务分开

数学节点记录稳定 ID、原题参数、精确对象域/命题、父节点、关系类型、已知结论、剩余义务及证据。partition 表示有证明的穷尽划分；local-family 表示只覆盖局部；dependency 表示证明或计算依赖；alternative 表示同一义务的替代方法。依赖允许形成 DAG，不能把共用引理重复画成互斥子类。

分枝数量按数学结构决定。固定的是节点身份及本批边界，不是所有码统一固定 N 枝。需要拆分时保存修订号、父域和补集；旧 ID 保留重定向/被包含关系。多个子域相交时明确记录交集未知，不用子节点计数之和当父域计数。

任务记录 task_id、所服务节点、输入矩阵/位序、操作与目标、依赖、区块、输出、验收条件、真实恢复入口。不同任务可能服务同一节点；同一任务也可能服务多枝。协调者在派发前登记唯一在途尝试与写目录，收回后解除，避免多个 worker 同时接同一块。用户暂停时只整理，不派任务。

任务的 queued/running/interrupted/completed 与数学上的未解/候选/已核见证/限定域排除分开。completed 只表示本项交付完成。UNKNOWN、超时、进程退出和没有真实数组检查点的部分运行不能计作完整覆盖。

## 3. ECC 的身份与剪枝

固定坐标的二元线性码按实际 GF(2) 行空间识别：统一 n、位序后消元得到规范基，比较秩及规范基。哈希可作索引，判定仍须绑定实际输入；同谱不证明等价。坐标置换等价需显式置换并核变换后的行空间；找不到置换只说明未知。

复用键还必须包含操作、目标和范围。相同母码的“全部一行扩张”排除可以覆盖其正交或非正交子集；仅正交排除不能反向关闭全部扩张。完整排除距离≥d，也排除同域更高目标，但不排除更低目标。对象改变后的正证明运输与旧否证适用范围分别检查。

包含关系可直接剪枝：若所有含 S 的目标码已排除，则所有含 T 的目标码在 S≤T 时也被排除。反方向不成立。删除坐标、缩短、取子码等操作须重算 n/k/d 和量词，不能凭谱相似或名字沿用闭合。

## 4. 回收、核验和向父节点传播

执行者交回同一 node_id/task_id、真实输入、读域、结果、未完成部分和证据。协调者先消费结果，再调用 ecc-certificate 检查明确局部义务。候选提交实际矩阵及原题所需验距；满足原存在性目标即可进入原题验收，不必等其它叶子关闭。

局部排除回写该域。父节点关闭前必须核对：子域覆盖父域的证明；每项必要子结论的准确假设和证据；仍有无 remainder；依赖是否失效。模型一致意见、全部任务显示 completed 或多数分枝被排除，都不替代这些条件。若覆盖命题本身未证，父节点继续未解。

证据被纠正时，保留旧版本，把使用它的节点与任务标为待重新核对，沿依赖追踪到受影响父结论；无关结果继续有效。修补先回原义务，不从头调查整题。

## 5. 当前快照、树图和剩余量

节点账本是当前状态入口，wiki 保留可复用知识与原证据引用，NEXT_SESSION 只链接当前节点、直接依赖和下一行动。更新替换过期下一步，历史移入原记录，不删除证据。重启先读准确断点，不能把摘要里漏掉某结论当作未研究。

树图从同一账本呈现每个叶子的结论、范围、剩余量及未闭接口；算法区块和共用依赖另列。人工或现有 render-html 均可生成，图不是第二个验收器。每个“0”标精确域；数量必须写单位（标签、母码×标签对、子空间或坐标等价类）及去重情况。只扣去一个完整闭合切片得到的是包络/上限，不是合格候选数；全局未知就写未知。任务数比例不代表原题完成比例。

每批前及收件后仍执行 base 的全局进展重评：稳定节点防重复，但不能成为一直追同一无收益路线的理由。若节点结论没有减少原题缺口，比较其它未解节点与实际总成本后再选下一批。
